# CARLA 자체 렌더링 버전 (50번)

2026-10-29 추가. NuRec 실사 재구성 화면의 잔상·차량 외형·합성 경계가
실험 몰입을 방해할 수 있다는 피드백에 따라 별도 버전을 만들었다.
기존 36/47/48/49 실행 파일과 NuRec 데이터는 보존한다.

## 무엇이 달라졌나

- **NuRec 버전:** 실제 촬영 장면을 신경 렌더러로 재구성하고 CARLA 상태에 연결한다.
- **50번:** CARLA의 도로·차량·조명·날씨·RGB 카메라를 사용한다.
  NVIDIA 모델 로딩, WSL, 렌더링 컨테이너가 필요 없다.
- 지도는 CARLA 기본 **Town04의 약 3,050m 4차로 순환 고속도로**다.
  서강로 또는 NVIDIA 촬영지의 실측 복제가 아니다.
- 우리 차와 앞차는 물리 주행을 한다. 앞차를 좌우로 순간이동시키지 않고
  조향 목표를 연속적으로 변경한다. 빠른 차량은 전방 205m 밖에서 뒤쪽으로
  재배치해 교통 흐름을 반복한다. 모든 차량이 무한한 세계를 주행하는 것은 아니다.

## 실행

수업 폴더 `CARLA-YOLO-실습`의 **50-CARLA-Native-Scenarios.bat**을 실행한다.
저장소에서는 `Start-CARLA-Native.bat` 또는 다음 명령을 사용한다.

```powershell
python launch_native_carla.py
```

1. 시작 화면에서 정체 / 야간 졸음운전 차량 / 짙은 안개를 선택한다.
2. 차량 준비 후 별도의 큰 주행 창이 열리고 브라우저는 기존 내비로 이동한다.
3. 내비의 **주행 시작**을 누른다.
4. 상황 발생 후 왼쪽 아래 **홍익 AI**가 점멸한다.
5. 설명을 열고 대응을 선택한 뒤 **실행**을 누른다.
6. 실제 결과를 최소 12초 관찰하고 정지·종료 안내를 확인한다.

앱: `http://127.0.0.1:8774/` / 내비: `/navigation` / 큰 영상: `/drive`.
큰 영상 창의 **전체 화면** 버튼을 사용할 수 있다.
별도 주행 창에서는 **F11** 전체 화면, **Space** 시작/일시정지를 사용한다.
브라우저의 팝업 허용 여부와 관계없이 별도 주행 창을 실행한다.
종료는 `50-Stop-CARLA-Native.bat` 또는 `Stop-CARLA-Native.bat`.

NuRec과 PC 내비 포트 8774를 공유하므로 **동시에 실행하지 않는다**.
50번은 기록된 NuRec 프로세스만 확인 후 정리한다. 다시 NuRec을 실행하려면
50번 종료 파일로 닫은 뒤 48번을 실행한다. 다른 CARLA/사용자 앱은 강제 종료하지 않는다.

## 세 시나리오

| 조건 | 연출 | 현재 대응 옵션 |
|---|---|---|
| 4차로 정체 | 2차로 우리 차와 앞차, 오른쪽 대형 트럭 3대, 왼쪽 빠른 차량 14대 | 하이빔 / 클락션 / 차간 거리 넓히기 / 그냥 유지 |
| 야간 졸음운전 차량 | 우리 차는 같은 차로 유지, 가까운 앞차가 오른쪽 차선 경계 주변에서 좌우로 흔들림 | 클락션 / 차간 거리 넓히기 / 그냥 유지 |
| 짙은 안개 | 10초까지 맑음, 10~15초 안개 증가, 이후 짙은 상태 유지·감속 | 현재 안전조치 확인 / 더 감속하고 거리 확보 / 안전한 곳에 정차 요청 |

각 조건은 주행 시간 기준 300초이며, 일시정지 시간은 제외한다.
대응을 실행하면 5분이 되기 전에도 결과를 관찰하고 해당 체험을 종료한다.
안개 정차 요청은 갓길 주차를 완료하는 기능이 아니다. 정차 가능한 장소를
확인하지 못한 상태에서는 감속·거리 확보를 수행하고 **부분 이행**으로 표시한다.
추월/충돌 분기는 이 기본 버전에 포함하지 않는다.

## 주요 설정과 수정 위치

| 설정 | 값 / 위치 |
|---|---|
| 기본 영상 | 1280×720, 센서 출력 목표 30fps |
| 선택 영상 | 360p / 540p / 720p / 1080p, 내비에서 변경 |
| 내비의 작은 3D 화면 | 최대 24회/초, 픽셀비 최대 1. 주행 카메라와 GPU 경쟁 완화 |
| 물리 실행 | 비동기, 기본 엔진 그래픽/DX 설정 유지 |
| 제어 전송 | 최대 약 30회/초, 차량 제어를 CARLA 비동기 배치로 전달 |
| CARLA RPC | 2026 (NuRec의 2016과 구별) |
| 정체 속도 목표 | 앞차 27~33km/h, 오른쪽 트럭 25~35km/h, 왼쪽 90km/h |
| 야간 초기 간격 목표 | 범퍼 간 6.5m → 거리 확보 요청 시 28m |
| 안개 초기 간격 목표 | 범퍼 간 8m → 거리 확보 요청 시 36m |
| 시간·옵션·물리 제어 | `native_carla.py` |
| 순환 경로·조향·안개 증가 함수 | `native_carla_route.py` |
| 시작 화면 | `native_home.html` |
| 기존 내비 연결 | `NativeNavigation`, 기존 `navigation_adapter.py` 명령 프로토콜 재사용 |

설정은 목표값이다. 실제 속도·간격은 차량 동역학에 따라 달라지며 내비에는
실제 CARLA 차량 상태를 표시한다. 경적은 브라우저에서 소리로 표현하고,
하이빔은 CARLA 차량의 실제 상향등 상태를 두 번 점멸시킨다.

## 음성과 아이폰

홍익 AI 클릭 시 기존 Qwen Sohee 사전 합성 캐시를 재생한다.
주행 중 음성 모델을 새로 올리지 않으며 마이크·음성 호출은 시작하지 않는다.
음성 파일/매니페스트는 기존 로컬 `../cache/sohee-narration/`가 필요하다.
없으면 설명은 텍스트로 제공하며 다른 목소리로 몰래 대체하지 않는다.

50번 시작기는 기존 휴대폰 게이트웨이도 준비한다.
기존 PC 내비의 **휴대폰 연결 · QR**을 사용한다. 아이폰 인증서/페어링/알림 허용은
기존 설정을 따른다. 이번 CARLA 전환의 PC 검증과 과거 아이폰 검증은 구분한다.

## 검증과 한계

`python -m unittest test_native_carla test_navigation_adapter`는 선택 전 실행 금지,
중복·오래된 세션 명령 거부, 일시정지 시 시간 보존, 실제 간격과 결과 종료를 검사한다.
`validate_native_carla.py`는 실행 중인 실제 CARLA에서 영상 프레임·차로 추종·간격·
명령 이행·종료를 확인한다. 상세 결과와 이미지는 로컬 `validation/`에만 보관한다.

30fps는 센서의 목표다. 내비 동시 표시·교통량·GPU 상태에 따라 변동할 수 있으며
브라우저 화면의 최종 표시 FPS나 연구실 3면 성능과 동일하지 않다.
로컬 정체 조건은 30fps 고정에 도달했다고 할 수 없다.
실제 사람의 졸음/위험을 감지하는 시스템이 아닌 **시나리오 기반 HMI 실험 도구**다.
참가자 연구나 불안 감소 효과가 검증됐다는 의미도 아니다.

## 별도 PC로 옮길 때

CARLA 0.9.16 (Town04 포함)과 해당 Python 버전에 맞는 CARLA 모듈,
`numpy`, `scipy`, `Pillow`가 필요하다. 기존 내비 웹 에셋은 `course_ui/`에 있다.
기본 시작 경로는 현재 PC를 기준으로 하므로 `launch_native_carla.py`의 CARLA 위치와
배치 파일의 Python 위치를 맞춘다. 원본 NVIDIA 장면이나 모델 데이터는 필요 없다.
휴대폰 게이트웨이와 Sohee 오디오는 각각 별도의 선택적 로컬 자원이다.
