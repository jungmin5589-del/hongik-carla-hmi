# 참가자 기록 · 응답 음성 · 중국어

기존 Three.js 내비게이션의 차량·지도·음악과 A/B 대응 구조를 유지합니다.
시나리오 선택 화면 오른쪽 위 **관리자 · 실험 기록**에서 기록을 확인합니다.

## 사용하는 순서

1. 기존 CARLA 시작 파일을 실행하고 PC에서 `http://127.0.0.1:8774/`를 엽니다.
2. 참가자 이름 또는 ID를 등록합니다. 연구에서는 `P001` 같은 ID 사용을 권장합니다.
3. 한국어 / English / 中文（简体）와 조건 A/B, 시나리오를 선택합니다.
4. 기존 내비에서 출발합니다. 홍익 AI 설명을 연 뒤 대응을 선택하고 실행합니다.
5. 선택 확인 → 요청 접수 → 진행 → 실제 결과 → 종료를 음성으로 안내합니다.
6. 종료 후 시나리오 선택으로 돌아가 다음 상황을 고릅니다. 같은 참가자는 유지됩니다.
   다음 사람은 새 이름/ID로 등록합니다. 앱 서버를 다시 켜면 참가자를 다시 등록해야 합니다.

아이패드는 기존 `/m/navigation` 연결을 사용합니다. 전체 내비와 같은 음성을 재생하며,
관리자와 전체 참가자 목록은 아이패드에 공개하지 않습니다. 기기 음량·자동 재생 정책에 따라
첫 출발/버튼 클릭이 필요할 수 있습니다. 여러 내비 탭을 동시에 켜두지 않는 것이 좋습니다.

## 어떤 기록이 남나

| 구분 | 내용 |
|---|---|
| 참가자 | 입력 이름/ID, 내부 식별자, 등록 시각 |
| 실행 | 시나리오, A/B 조건, 선택 언어, 준비·출발·종료 시각 |
| 행동 | 알림/설명/선택지 UI 노출, 선택, 취소, 실행 확인, 실제 동작, 결과 |
| 시간 | 출발 후 경과 초, 상황 발생 후 경과 초, 기록 수신 UTC 시각 |
| 결과 | 완료·일부 완료·완료 확인 불가 등 실제 시나리오 상태 |

관리자 목록은 첫 선택과 첫 실행 확인 시점을 표시합니다. 행을 누르면 재선택과 취소를 포함한
전체 타임라인을 봅니다. CSV 두 종류로 내려받을 수 있습니다. UTC 원본은 관리자에서 PC 현지
시각으로 표시하며, CSV는 UTF-8 BOM과 셀 수식 방어를 적용합니다.

시간은 서버가 요청을 받은 시점의 **일시정지 제외 주행 시간**입니다. 기기의 물리적 터치 시각과는
통신 지연만큼 차이가 있습니다. UI 표시 기록은 시선·읽기·이해를 측정한 값이 아닙니다.
참가자가 등록되지 않은 개발용 API 주행은 참가자 DB에 포함하지 않습니다.

PC 저장 위치는 `%LOCALAPPDATA%\HongikDriveResearch\research.sqlite3`입니다.
외장 D가 끊겨도 이미 기록된 DB는 C에 남습니다. 관리자 주소는 PC의
`http://127.0.0.1:8774/admin`이며 LAN 게이트웨이는 이 경로를 전달하지 않습니다.

## Google Drive 자동 동기화

기존 배포 폴더와 분리한 새 **비공개 ‘홍익 주행 실험 기록’** 폴더를 사용합니다.
PC용 Google Drive에 해당 계정으로 로그인해야 자동 동기화됩니다.
채팅의 Google Drive 연결만으로 PC 백그라운드 업로드가 작동하지는 않습니다.

PC의 비공개 `drive-config.json`과 Drive 폴더 안 `.hongik-research-target.json`이 가리키는
폴더 ID·표식이 모두 일치할 때만 복사합니다. 폴더 이름이 같은 다른 계정에는 쓰지 않습니다.
기록 변경 후 CSV 두 파일과 SQLite 스냅샷을 자동 갱신하고, 연결이 끊기면 PC 기록을 유지하며
다시 연결될 때 재시도합니다. Drive 앱의 일반 스트리밍 경로를 자동 탐색합니다.

- **PC에 저장 중**: 로컬 DB·내보내기만 사용합니다.
- **Drive 앱 로그인·폴더 연결 대기**: PC 기록은 정상이며 클라우드 연결이 필요합니다.
- **Drive 동기화 폴더에 기록됨**: 파일 복사가 완료됐습니다. 클라우드 업로드 완료 여부는 Drive 앱에서 확인합니다.
- **Drive 동기화 오류**: PC 원본은 보존합니다. 앱 연결/디스크 상태를 확인합니다.

새 연구실 PC에서는 같은 개인 Drive 계정으로 로그인하고, 비공개 로컬 설정 파일을 별도 전달해야
합니다. `drive-config.json`과 참가자 DB는 GitHub에 넣지 않습니다. 이 방식은 단일 실험 PC에서
클라우드로 백업하는 구조입니다. 여러 PC가 같은 파일을 동시에 덮어쓰는 공동 DB는 아닙니다.

## 음성과 중국어

한국어·영어 응답은 Qwen3-TTS 0.6B의 **Sohee**, 중국어 안내와 응답은 같은 모델의 **Vivian**입니다.
중국어 외부 인물 대사는 **Uncle_Fu**를 사용합니다. 간체자 화면과 표준중국어 음성을 연결합니다.
경적·차량 움직임·낙하물 효과음은 언어를 바꿔도 같습니다. 음성은 합성 음성입니다.

자주 쓰는 선택·실행·결과 문장을 미리 합성해 WAV 캐시에 저장했습니다. 주행 중 모델을 다시
학습하거나 GPU에서 실시간 합성하지 않으므로 응답을 빠르게 시작합니다. 설명과 응답 음성이
겹치지 않게 재생 권한을 공유하고 음악은 줄였다 복구합니다. 실패/부분 완료 상태를 성공으로
읽지 않도록 실제 결과 상태에 따라 응답을 고릅니다.

캐시는 `../cache/research-voice`에 있으며 공개 저장소에는 포함하지 않습니다.
다른 PC에서는 이 캐시를 별도 전달하거나 주행을 중지한 상태에서
`python prepare_research_audio.py`를 실행합니다. 기존 로컬 Qwen 모델과 TTS 환경이 필요합니다.
음성 문구를 변경하면 다시 생성합니다. 한국어 설명용 기존 캐시도 계속 필요합니다.

## 검증 범위

실제 SQLite 저장·재시작 후 보존·선택 취소 보존·시간 계산·CSV·폴더 표식 검증을 검사했습니다.
분리된 브라우저 검증에서는 중국어 등록/설명/선택/결과 음성, 음성 중복 방지,
관리자 타임라인을 확인했습니다. 이 검증 데이터는 임시 폴더만 사용하며 실제 참가자 DB에 넣지 않습니다.
음성 캐시 79개는 무결성과 WAV 형식·무음 여부를 확인했습니다.
분리된 UI 검증은 실제 CARLA 물리 동작 또는 실제 아이패드에서의 신규 기능 검증을 대신하지 않습니다.
