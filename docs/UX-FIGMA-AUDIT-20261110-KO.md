# 피그마 UX와 현재 앱 비교

2026-11-10 · 내일 UX 테스트 전 적용 상태 확인. 앱 동작·디자인은 수정하지 않았다.

**판단:** 준호의 공통 정보 구조와 여섯 상황의 선택지는 대부분 적용됐다.
다만 관제 영상통화, 상시 도어 잠금 확인, 자가진단 정상 화면, 결과별 시각 피드백은 원안과 차이가 있다.
공통 인터페이스 사용성 점검과 원안 전체 기능의 효과 검증을 구분해야 한다.

`/navigation`을 열더라도 47번 NuRec 또는 classic 경로를 실행했다면 같은 최신 UX라고 볼 수 없다.
기본 B는 패시브+능동 요청, A는 패시브+고정 도움/정차 요청이다.

## 공통 UX 비교

| 피그마 의도 | 현재 앱 | 상태 |
|---|---|---|
| 기존 내비 위에 상호작용 | Three.js 차량·지도·음악·하단 컨트롤 유지 | 적용. 회색 와이어프레임 스킨 복제는 사용자 요청으로 제외 |
| 차가 인식한 상황과 현재 대응을 상시 표시 | 차량 상태 카드의 제목·설명 | 가로 화면 적용. 폭 800px 이하에서는 숨김 |
| 아래쪽 작은 알림과 자세히 보기 | 왼쪽 아래 홍익 AI 버튼이 1.4초 주기로 2회 강조, 이후 표시 유지 | 형태 변경. 음성 호출·자동 상세창 없음 |
| 알림 자체 X, 상세창 X | 상세창 X와 Esc 제공. 작은 알림용 별도 X는 없음 | 일부 차이 |
| 지금 상황 / 차가 하고 있는 일 | 상세창 왼쪽에 별도 카드 | 적용 |
| 세로 선택지 3~4개와 별도 그냥 둘게요 | 상세창 오른쪽 세로 리스트·별도 유지 버튼 | 적용 |
| 선택지별 ETA 제거 | 선택지에 ETA·도착 시간 없음 | 적용. 기본 내비의 ETA 표시는 별개 |
| 선택 후 요청과 결과 확인 | 선택 → 실행 확인 → 3초 취소 → 실제 상태 확인 → 결과 관찰 | 적용 |
| 결과별 작은 시각 팝업과 확인/한 번 더 | 기존 큰 상세창의 결과 요약·현재 화면, 일부 동작 반복, 완료 후 종료창 | 기능 적용, 결과 전용 시각 구성은 일부 차이 |
| A 패시브 / B 패시브+알림·선택·결과 | 선택 화면에서 A/B 수동 선택 | 적용. 배정·순서 무작위화는 없음 |
| 요청 결과 이후 다음 장면 | 결과 약 12초 관찰 후 정차, 선택 화면으로 복귀 | 사용자 후속 요청 반영. 다음 상황 자동 실행은 아님 |

설명과 선택지는 같은 상세창에 함께 표시된다. 설명을 반드시 끝까지 들은 뒤 선택하도록 강제하지 않는다.
이는 준호의 최종 화면 흐름과 맞으며, 앞선 구상에 있던 ‘정보만 보기 → 별도 옵션 열기’와는 다르다.

## 여섯 상황의 실제 선택지

모든 B 상황에 **그냥 둘게요**가 추가된다. 선택만으로 동작하지 않고 실행 확인이 필요하다.

| 상황 | 현재 선택지 | 피그마와의 관계 |
|---|---|---|
| S1 정체 | 트럭과 거리 넓히기 / 1차로로 진입하기 / 근처에서 내리기 | 준호 최종안과 일치 |
| S2 안개 | 주변 인식 화면 보기 / 더 천천히 가기 / 갓길에 세우기 | 행동 범주 일치. 실제 센서 150m 화면은 아님 |
| S3 졸음운전 | 클락션 / 거리 더 넓히기 / 안전할 때 앞질러 가기 / 갓길에서 잠시 기다리기 | 원안 신고/관제 항목을 사용자 요청대로 클락션으로 교체 |
| S4 보행자 | 먼저 건너라고 알리기 / 천천히 출발하기 / 여기서 내리기 | 준호 최종안과 일치. 예전 대화의 경적/하이빔/직접 대화 버전과는 다름 |
| S5 카풀·취객 | 관제 센터 연결 / 지금 바로 출발하기 / 안전한 곳으로 옮겨서 내리기 | 선택지 문구는 반영. 실제 관제 통화 화면 미구현 |
| S6 이상음 | 차량 상태 자세히 보기 / 천천히 가면서 점검하기 / 갓길에 세우고 점검하기 | 행동 범주 일치. ‘자가진단 정상’이라는 상황 설명은 다름 |

낙하물은 추가 7번으로 남아 있다. 여섯 상황 UX 테스트를 한다면 운영자가 대상 범위를 따로 고정해야 한다.

## 내일 테스트에 영향을 주는 차이

### 1. 관제 연결은 통화 구현이 아니다

피그마에는 LIVE 영상·연결 시간·상담원 확인·통화 종료가 있다.
현재는 로컬 지원 요청 상태만 제공한다. 약 8초 후 부분 완료로 처리하고 실제 상담원 연결이 확인되지 않았다고 안내한다.
원격 상담원의 도움 경험을 평가할 수 있는 완성 상태는 아니다.

### 2. 도어 잠금 확인 카드가 없다

피그마에는 상시 ‘도어 4개 모두 잠김 / 확인’이 있다.
코드의 상태 데이터에는 카풀용 `door_locked`가 있지만 패널은 이를 상시 잠금 카드로 표시하지 않는다.
지금 상세 설명은 ‘문을 닫은 채 대기’이며, ‘문이 잠겼는지 확인하기’ 과제는 원안대로 수행하기 어렵다.

### 3. 이상음의 연구 상황이 달라졌다

피그마는 **불편한 소리와 달리 차량은 자가진단 정상이라고 판단하고 계속 주행**하는 상황이다.
현재 설명은 **원인이 아직 확인되지 않아 상태를 살피는 중**이다.
또 상태 보기는 속도·주변 위치 중심이며 타이어·하부·센서 진단표를 제공하지 않는다.
이는 문구 차이를 넘어, 승객이 의심하는 대상과 선택 이유를 바꿀 수 있는 차이다.
자가진단 화면을 추가한다면 실험에서 가정한 진단 상태와 실제 CARLA가 제공하는 정보를 구분해야 한다.

### 4. 결과의 시각적 설명이 원안보다 단순하다

피그마의 측면 간격 +0.5m 전용 그림, 정차 지점 표시, 잠금 확인, 관제 통화 화면을 모두 갖춘 상태는 아니다.
현재는 결과 요약·일부 주변 위치 표시·실제 정면 화면·음성을 사용한다.
‘어떤 버튼을 골랐나’와 별개로 ‘결과를 알아차렸나’를 관찰할 필요가 있다.

### 5. 작은 화면의 A 조건에서 기본 정보가 사라진다

현재 CSS는 화면 폭 800px 이하에서 차량 상태 카드를 숨긴다.
자동 브라우저 확인에서 가로 1194×834는 A의 상태 카드와 고정 요청이 보였지만,
768×1024 세로에서는 상태 카드가 숨겨졌다.
내일 수정 없이 비교한다면 **같은 기기·같은 가로 방향**으로 고정하는 것이 필요하다.
브라우저 크기 모의 확인이며 실제 iPad Safari의 신규 검증을 대신하지 않는다.

### 6. 4-Step 평가 전체가 앱에 들어간 것은 아니다

등록·설명 열기·선택·실행·취소·결과 시간은 DB/관리자/CSV로 남는다.
하지만 상황 이해 정답, 불안감 전후, 정보 충분성, 결과 이해, 재사용 의향의 설문 화면·점수는 없다.
설명 열기 시간은 실제 인지 시점이나 읽기 완료 시점이 아니다.
이 항목을 내일 평가하려면 별도 질문지·관찰 기록을 사용하거나 후속 구현이 필요하다.

### 7. 조건 선택 화면은 운영자가 관리해야 한다

선택 화면에 ‘인터페이스 조건 A/B’가 그대로 보이고, 전체 아이패드 내비에서 종료 후 그 선택 화면으로
돌아갈 수 있다. 아이패드는 관리자 링크를 숨기지만 조건 선택까지 숨기지는 않는다.
조건을 참가자가 임의로 바꾸거나 연구 목적을 미리 추측하지 않게 하려면, 현재 상태에서는 운영자가
등록·조건·시나리오를 준비한 뒤 참가자에게 주행 내비 화면을 전달하는 방식으로 진행해야 한다.
자동 무작위 배정이나 참가자용 설정 잠금은 구현돼 있지 않다.

## 사용자 후속 요청으로 의도적으로 달라진 것

- 회색 스킨 대신 기존 테슬라형 내비를 유지했다.
- 졸음운전의 신고/관제 항목은 클락션으로 바꿨다.
- 정체의 앞차·대형차 속도는 피그마 예시 60km/h 대신 사용자가 원한 25~35km/h 변동이다.
- 취객은 심야 원안 대신 사용자가 선호한 밝기로 돌아갔고, 뒤에서 목소리로 먼저 접근한다.
- 종료 전 행동 결과를 충분히 보여주고 정차·종료 안내·선택 화면 복귀를 제공한다.

이 차이는 누락과 구분한다. 내일 테스트 설명 자료가 과거 피그마 수치·야간 조건을 그대로 말하지 않도록 맞춰야 한다.

## 내일 우선 확인할 UX 과제

1. 안내 없이 새 상황 알림을 발견하는가?
2. ‘지금 상황’과 ‘차가 하고 있는 일’을 구분해 설명할 수 있는가?
3. 선택지와 ‘그냥 둘게요’의 의미를 이해하고 원하는 요청을 고르는가?
4. 선택·실행·3초 취소를 구별하고 취소할 수 있는가?
5. 동작 결과를 알아차리고, 결과가 자신의 요청과 맞는지 말할 수 있는가?

관제 통화·문 잠금·자가진단 정상 과제를 포함할지는 원안과의 차이를 먼저 정리해야 한다.
이는 현재 적용 상태에 대한 우선순위 제안이며 참가자 연구 결과가 아니다.

## 확인 방법과 한계

Figma 원문·공통 흐름 이미지와 현재 코드를 대조했다. 실제 앱 HTML/JS에 합성 상태를 제공해
B 여섯 상황의 세로 정렬·ETA 미표시·실행 확인창, A의 AI 버튼 숨김·고정 요청·가로/세로 상태 카드 차이를 확인했다.
브라우저 오류는 없었고, 상태·취소·기록 관련 Python 검사 19개도 통과했다.
이 확인은 실제 주행·물리 모션·장치 성능·실제 참가자 데이터와 구분한다.
합성 상태의 지도·차량 배치는 실제 시나리오 장면의 재검증 자료가 아니다.
상세 캡처·합성 데이터는 로컬 `validation/ux-audit-20261110`에 보관하고 공개 Git에는 넣지 않는다.
