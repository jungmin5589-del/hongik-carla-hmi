# 중간 정리 → 승객 내비게이션과 CARLA 동작

2026-11-06. Figma `1104 중간 정리`(499:653)를 읽고, 준호의 11개 흐름(552:1780, 552:2, 552:279, 552:617, 552:872, 552:1030, 552:1886, 552:2231, 552:1550, 552:1202, 552:1380)을 실제 앱에 연결했다.

원본: [팀 Figma](https://www.figma.com/design/DvOJDrOFPuiN066rXoa7g1/human-autonomous-driving?node-id=499-653).
와이어프레임 전체 텍스트와 주요 화면을 확인했다. Figma 안의 연구 아이디어는 요구사항의 근거이며, 참가자 실험 결과로 취급하지 않는다.

## 실행

기존 **50번 CARLA 실행** 또는 `python launch_native_carla.py` → 선택 화면에서 시나리오와 A/B 조건 선택 → 내비의 **출발**.

- `http://127.0.0.1:8774/`: 운영자 선택 화면
- `http://127.0.0.1:8774/navigation`: **기존 테슬라형 내비를 유지**하고 중간 발표의 상호작용을 얹은 화면
- `http://127.0.0.1:8774/drive`: 별도 큰 실제 CARLA 영상
- 기존 내비 HTML: `/navigation/classic`. 기존 시나리오 동작까지 비교하려면 `/api/select`에 `presentation: classic`을 명시한다.

NuRec는 이번 적용에서 변경하지 않았다. 실제 물리 차량·보행자는 CARLA native 경로에서 실행한다. 해상도/음악/주행음/기존 Sohee 캐시를 유지한다.

### 디자인 적용 범위

사용자 최종 요청에 따라 기존 `course_ui/index.html`, `cockpit.css`, `cockpit.js`의 3D 차량·색상·지도·음악 도크·하단 컨트롤을 유지한다. 준호의 회색 와이어프레임은 스킨으로 복제하지 않는다. **버튼 위치, 정보 구조와 행동 흐름**만 기존 홍익 AI 패널에 적용한다. 초기에 만든 회색 화면은 사용 경로에서 제거했고 로컬 검증 폴더에만 남겨둔다.

## 공통 UX

1. 평소: 오른쪽 상태 카드에 **차량이 파악한 상황과 현재 대응**을 표시한다.
2. B 조건: 기존 왼쪽 아래 **홍익 AI** 버튼이 두 번 은은하게 강조되고 남는다. 자동으로 설명창을 열거나 음성을 호출하지 않는다. 설명창에는 항상 X가 있다.
3. 클릭: 왼쪽 **지금 상황 / 차가 하고 있는 일**, 오른쪽 **동등한 세로 선택지**를 표시한다. 선택지에 ETA를 붙이지 않는다. **그냥 둘게요**는 별도 텍스트 버튼이다.
4. 선택만으로 차가 움직이지 않는다. 요청 확인창에서 **실행**을 눌러야 한다.
5. 실행 후에도 **주행 시간 기준 3초** 동안 취소할 수 있다. 일시정지 중에는 카운트다운도 멈춘다.
6. 물리 차량이 동작한다. 실제 상태로 결과를 확인하고 약 12초간 결과를 보여준 뒤 감속·정차한다. 완료 안내를 내비에 보낸다.
7. 경적/거리 확보 등은 결과 관찰 중 **한 번 더** 요청할 수 있다. 실행 후 중단은 순간적으로 되돌리는 대신 차량을 감속·정지시킨다.

고정 **도움 요청 / 정차 요청**은 A/B 모두 있다. A는 추가 배너와 상황별 선택지를 숨긴다. 선택 화면에서 조건을 정하며, 참가자 화면에는 조건명·‘체험’이라는 표현을 넣지 않는다. 설정 서랍은 운영자용이다.

## 여섯 상황과 동작

| 상황 | 세로 선택지 | CARLA 반영 |
|---|---|---|
| 정체·트럭 사이 서행 | 트럭과 거리 넓히기 / 1차로 진입 / 근처에서 내리기 | 차로 안에서 약 0.5m 이동, 왼쪽 공간 확인 후 차로 변경, 실제 주차·갓길 확인 후 정차 |
| 짙은 안개 | 주변 인식 화면 / 더 천천히 / 갓길 정차 | 주변 물리 객체의 위치를 확대 표시, 12km/h 이하 목표, 실제 정차 공간 확인 |
| 졸음운전 앞차 | **클락션** / 거리 더 넓히기 / 안전할 때 앞질러 가기 / 갓길 대기 | 경적 1회, 목표 간격 28m, 안전 확인 후 왼쪽 추월, 정차 공간 확인 |
| 횡단보도 보행자 | 먼저 건너라고 알리기 / 천천히 출발 / 여기서 내리기 | 기존 캐시 외부 음성, 실제 보행자가 횡단 구간을 벗어났을 때만 출발, 정차 공간 확인 |
| 야간 카풀 대기 | 관제 센터 연결 / 바로 출발 / 안전한 곳에서 내리기 | 지원 요청 상태 연출, 외부인이 물러난 뒤 검증된 주차 구역 안에서 6m 이동·정차 |
| 반복 이상음 | 차량 상태 보기 / 천천히 점검 / 갓길 점검 | 상태·실제 주변 위치 표시, 저속 주행, 주차·갓길 확인 후 정차 |

각 상황에는 **그냥 둘게요**가 추가된다. 낙하물은 기존 일곱 번째 추가 상황으로 보존하고 같은 공통 UX에 연결했다.

졸음운전의 관제센터 항목은 사용자 요청대로 **클락션으로 교체**했다. 기존 강제 사고 `overtake`와 새 안전 확인 `pass`는 별개이며, 새 선택지는 강제 충돌 연출을 호출하지 않는다.

## 실제 데이터와 연출의 경계

- 내비 차량·보행자·차로는 CARLA 물리 객체 위치다. YOLO, 실제 차량 센서, 실제 LiDAR 화면이라고 표시하지 않는다.
- ‘센서 150m’, ‘정상 100%’, ‘상담원 연결됨’ 같은 와이어프레임의 임의 수치는 넣지 않는다.
- 관제 연결은 연구용 로컬 요청 상태다. 실제 운영센터·통신 연결은 없다. 결과에 상담원 연결이 확인되지 않았음을 표시한다.
- 문 닫힘은 CARLA 차량 상태, 잠금은 시나리오 상태다. 실제 문 잠금 장치와 연결되지 않는다.
- 정차 공간은 맵의 Shoulder/Parking 차로와 차량 전체가 들어가는 영역을 확인한다. 공간이 없으면 현재 위치 정지와 **미확인/부분 완료**로 안내한다. 안전 하차가 이뤄졌다고 기록하지 않는다.
- 보행자 출발 선택도 횡단 중 사람을 뚫고 진행하지 않는다.
- 정체는 실제 4차로 지형이다. 기존 빠른 차 흐름을 유지하다 진입 요청 때 뒤쪽 차량을 물리적으로 감속시켜 틈을 만드는 연구 연출이다. 자율차 간 실제 통신은 아니다.
- 단계 로그는 상황 발생 후 0/15/30초 구간 구분이다. 모든 상황의 물리적 자극이 동일한 비율로 커진다는 뜻은 아니다. 기존 안개·외부인·보행자 연출은 각자의 시간표를 유지한다.

## 측정과 파일

`native-runs`에 상황 시작, 단계, UI 노출, 열기/닫기, 선택, 명시적 실행, 실행 전 취소, 실행 시작, 반복, 결과 관찰, 완료를 기록한다. UTC·monotonic·주행 경과 시간을 구분한다. UI 노출은 실제 시선이나 이해도를 뜻하지 않는다.

- `midterm_panel.js/.css`: 기존 테슬라형 화면 위의 설명·세로 선택지·고정 요청·결과
- `midterm_audio.js`: 기존 Sohee/외부 음성/경적/이상음 연결
- `midterm_study.py`: 요청·취소·물리 결과 확인
- `native_carla.py`: 실제 주행 제어와 화면 제공
- `test_midterm_study.py`: 타이밍·취소·조건·결과 게이트
- `test_midterm_browser.cjs`: 실제 로컬 브라우저 버튼 흐름
- `validate_midterm_live.py`: 실제 CARLA 요청과 결과 저장

기존 홍익 AI 아이콘과 테슬라형 구성 요소를 사용한다. 런타임은 임시 다운로드 URL이나 Figma 스크린샷에 의존하지 않는다. 상세 캡처·로그는 로컬 D에 보관하며 Git에는 코드·문서만 올린다.

## 추가 피드백: 취객은 뒤에서 접근

차량 뒤 약 12m에서 시작한다. 약 3초에 기존 캐시의 첫 외침이 먼저 들리고, 걸어서 오른쪽 뒷좌석 유리창으로 접근한다. 접근 중에는 이동 방향에 맞는 CARLA 기본 보행을 사용하며 몸을 강제로 차량 쪽으로 돌리지 않는다. 창문 옆에서 실제로 멈추고 바라본 뒤 두드림과 ‘문 열어’ 대사가 이어진다. 첫 외침은 1회이며 나머지 대사는 실제 첫 두드림을 기준으로 진행한다. 가까워질수록 음량과 명료도가 올라간다.

주차 위치는 검증된 기존 위치를 유지한다. 차 안의 뒷좌석 눈높이·오른쪽 방향 카메라에서 창틀과 사람이 보이도록 조정했다. 차량·보행자 위치와 실제 카메라 캡처를 확인하며, 실제 유리 재질 변경이나 실사 인물 모델을 추가한 것은 아니다.

## 이번 검증

- Python 상태·요청·기존 시나리오·모바일 게이트웨이 검사 77개, 모바일 설정 JavaScript 검사 7개 통과.
- 실제 브라우저에서 기존 3D 차량 캔버스·지도·음악 도크가 유지됨을 확인. 클락션 선택만으로 실행되지 않는지, 3초 안 취소 시 미실행, 다시 실행 시 1회 동작, 결과 팝업 닫힘을 검사했다.
- A 조건은 능동 알림이 없고 상태 카드·고정 정차 요청이 표시되는지, 명시적 실행과 취소가 되는지 검사했다.
- 실제 CARLA에서 정체 차로 진입, 야간 클락션/왼쪽 추월, 안개 감속/갓길 정차, 보행자 양보 안내, 카풀 이동, 이상음 상태 보기, 추가 낙하물 정지를 각각 결과·정차까지 확인했다. 최근 해당 검사에서 접촉은 없었다. 모든 선택지 조합을 전부 장시간 시험한 것은 아니다.
- 취객의 첫 외침이 카메라 시야 밖에서 재생되고 이후 실제 창문 위치에서 두드림이 시작되는지, 브라우저 음성 재생과 이동 결과를 검사했다. 영상도 실제 창틀과 사람의 위치를 확인했다. 물리 스피커 위치·주관적 공포감 평가는 별개다.
- 차량 크기 조회가 프레임마다 엔진 왕복을 일으키는 지연을 확인하고 생성 때 저장하도록 바꿨다. 정체 제어 주기에서 약 0.5초→약 0.05초 사례를 확인했다. 이는 전체 표시 프레임 수나 안정적인 30fps 증명이 아니다.
- 휴대폰에는 새 선택지·취소·고정 요청과 상태 보기 노출을 호환시켰다. 이번 변경 뒤 실제 아이폰 잠금 알림을 다시 수신 시험하지는 않았다.

개발 검증은 참가자 실험·안전 인증·연구실 3면 화면 성능 검증을 대신하지 않는다. 30fps는 목표값이다.
