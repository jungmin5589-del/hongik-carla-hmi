# 우리 NuRec 주행 실험, 쉽게 이해하기

기준일: 2026-10-28 · 교수님·팀원과 공유하기 위한 설명서

**우리 코드는 주행 행동을 정하고, CARLA는 차량의 움직임을 계산하며, NuRec은 그 위치에서 보이는 실제 거리 같은 화면을 그린다. 내비게이션은 승객이 설명을 보고 대응을 선택하는 창이다.**

이 문서는 현재 `48`번으로 들어가는 NuRec 앱 기준이다. 기존 `36`번 앱과 시작 경로가 다르다. 최신 코드의 세부 변경은 Git 커밋 기록을 함께 확인한다.

## 1. 무엇을 조합해서 만든 건가?

| 구성 | 쉬운 설명 | 우리 프로젝트에서 하는 일 |
| --- | --- | --- |
| CARLA | 차량 움직임을 계산하는 시뮬레이터 | 우리 차의 위치·속도·조향·브레이크와 충돌 계산 |
| NuRec | 실제 촬영 자료로 복원한 3D 장면을 그리는 기술 | 현재 카메라 위치에서 보이는 도로·건물·차량 화면 생성 |
| Python 연결 코드 | 두 프로그램을 이어 주는 중간 담당자 | 시나리오 진행, 앞차 움직임, 우리 차 추종 제어, 위치·화면 연동 |
| 내비게이션 | 승객용 실험 인터페이스 | 지도, 홍익 AI 알림, 설명, 선택, 실행 결과 |
| 아이폰 연결 | 내비의 상황 확인·선택을 휴대폰에서도 제공 | 연결된 같은 주행의 알림과 대응 선택 |

NuRec은 실제 카메라·라이다 자료로 3D 장면을 복원하고 다른 시점의 화면을 생성할 수 있는 NVIDIA 기술이다. 우리는 제공된 **이미 학습된 장면**을 사용한다. 새 거리를 직접 촬영하거나 매번 처음부터 학습하는 방식은 아니다. [NVIDIA 공식 소개](https://docs.nvidia.com/nurec/), [복원·렌더링 설명](https://docs.nvidia.com/nurec/basics/how-nurec-works.html)

우리 앱은 CARLA의 현재 위치를 NuRec에 보내 새 화면을 요청한다. 그래서 실제 차량의 감속·정지·거리 변화와 화면을 연결할 수 있다. 사용한 원본 경로 근처에서의 시각 품질과 모델이 지원하는 편집 범위에는 한계가 있다. [CARLA 공식 NuRec 연동 설명](https://carla.readthedocs.io/en/latest/nvidia_nurec/)

## 2. 한 번의 상호작용은 이렇게 이어진다

1. 선택한 시나리오의 상황이 발생한다.
2. 내비의 홍익 AI 버튼이 상황 알림을 표시한다.
3. 승객이 버튼을 누르면 설명과 선택지가 열린다. 준비된 Sohee 음성도 재생한다.
4. 승객이 대응을 고르고 **실행**을 누른다.
5. 연결 코드가 실제 주행 제어에 요청을 반영한다.
6. 바뀐 위치를 CARLA에서 받아 NuRec 화면과 내비에 함께 표시한다.
7. 결과를 일정 시간 관찰한 뒤 주행을 멈추고 종료 메시지를 보낸다.

예를 들어 야간에 `차간 거리 넓히기`를 실행하면 우리 차가 감속하고, 앞차가 화면에서 실제로 멀어진다. 기본 결과 관찰 시간은 12초다. 조치가 완료되지 않았으면 완료됐다고 대신 표시하지 않는다.

현재 설명은 **우리가 정한 시나리오 상태**를 바탕으로 한다. 이 NuRec 경로에서는 자유 대화 LLM이나 YOLO 판단으로 설명을 생성하지 않는다. Sohee는 준비된 문장을 미리 합성한 음성을 재생한다. 자주 쓰는 대사를 미리 준비한 것이며, 우리 대화로 음성 모델을 재학습한 상태는 아니다.

## 3. 현재 세 가지 시나리오

각 조건은 독립적으로 선택한다. 서로 다른 원본 장면을 쓰므로 같은 길이의 동일한 맵이라고 해석하지 않는다. 아래 거리는 **차 앞뒤 범퍼 사이의 목표 간격**이고 실제 간격은 차량 제어에 따라 달라진다.

| 조건 | 어떤 상황인가 | 핵심 설정 | 현재 기본 선택지 |
| --- | --- | --- | --- |
| 4차로 정체·서행 | 우리 차는 2차로. 느린 앞차, 오른쪽 대형차, 왼쪽 빠른 흐름 때문에 답답한 상황 | 앞차·대형차 25~35km/h, 왼쪽 차량 목표 90km/h, 배치 간격 20m, 오른쪽 대형차 3대 | 하이빔 / 클락션 / 차간 거리 넓히기 / 그냥 유지 |
| 야간 불안정한 앞차 | 우리 차는 직진. 앞차가 두 차로 경계 쪽에서 좌우로 흔들림 | 흔들림 시작 6초, 앞차 약 11km/h, 기본 목표 간격 5.5m → 거리 확보 시 28m | 클락션 / 차간 거리 넓히기 / 그냥 유지 |
| 짙은 안개 | 출발 후 맑다가 안개가 짙어져 앞차만 희미하게 보임 | 주행 5분, 시작 10초, 농도 증가 5초, 15초 이후 짙은 상태 유지, 목표 간격 8m → 거리 확보 시 36m | 현재 안전조치 확인 / 더 감속하고 거리 확보 / 안전한 곳에 정차 요청 |

4차로의 기본 추종 목표는 7m, 거리 확보 목표는 26m다. 앞차와 트럭의 25~35km/h 범위는 순항 구간 기준이며 출발·구간 끝에서는 더 느려진다. 하이빔은 두 번 켰다가 끄는 화면 피드백을 제공한다.

야간의 기본 모드는 직진·앞차 흔들림이다. 추월·충돌 시험 분기는 별도 개발 모드이고 기본 세 가지 선택에 포함되지 않는다. 이전 기획의 `다른 경로 찾기`도 현재 기본 4차로 선택지에는 들어 있지 않다.

안개의 `정차 요청`은 현재 구간에 확인된 정차 공간이 없으면 감속·거리 확보로 대응한다. 실제 갓길 정차를 완료한 것처럼 안내하지 않는다. 안개는 프레임의 거리 정보로 합성한 시각 효과이며 실제 악천후에서의 센서 성능을 재현·검증한 것은 아니다.

시간은 **실제로 주행이 진행되는 시간**이다. 일시정지 시간은 제외한다. 선택한 행동의 결과 관찰을 마치면 전체 구간 끝에 도달하기 전에도 종료할 수 있다. 4차로 조건은 현재 촬영 구간의 끝까지 진행하며 임의로 길이를 늘리는 무한 루프가 아니다.

## 4. 지금 PC에서 켜는 방법

가장 쉬운 방법은 실습 폴더의 **`48-NuRec-Long-Congestion.bat`**를 실행하는 것이다. `.bat`는 필요한 시작 명령을 한 번에 실행하는 Windows 파일이다.

1. 외장 D 드라이브가 보이는지 확인한다.
2. `48`번을 실행한다.
3. 첫 화면에서 시나리오와 영상 설정을 고른다.
4. 준비가 끝나면 내비에서 `주행 시작`을 누른다.
5. `큰 주행 화면`으로 도로 화면을 별도 창에 띄울 수 있다.

터미널에서는 현재 설치된 전용 Python으로 시작한다.

```powershell
Set-Location 'D:\CARLA-Maps\NuRec-OneScene-20261018\live'
& 'C:\CARLA_0.9.16\diagnostics\nurec-env\Scripts\python.exe' open_app.py
```

| 화면 | 이 PC에서 여는 주소 |
| --- | --- |
| 시나리오 선택 | http://127.0.0.1:8775/ |
| 내비게이션 | http://127.0.0.1:8774/navigation |
| 큰 주행 화면 | http://127.0.0.1:8774/drive |
| 휴대폰 연결·QR | http://127.0.0.1:8776/connect |

`127.0.0.1`은 **이 PC 자신**이라는 뜻이다. 아이폰에는 휴대폰 연결 화면이 보여 주는 QR/주소를 사용한다.

같은 장면이 이미 준비돼 있으면 재사용할 수 있다. 다른 시나리오를 처음 선택하면 큰 원본 모델을 읽고 GPU를 준비하므로 수분이 걸릴 수 있다. 준비 시간과 주행 중 프레임 속도는 다른 문제다.

## 5. 세팅값은 어떻게 읽으면 되나?

| 항목 | 현재 기본값 | 의미 |
| --- | --- | --- |
| CARLA | 0.9.16, DX12 | 우리 PC에서 맞춰 둔 엔진·Python API 버전 |
| 물리 계산 | 비동기 방식 | 화면 한 장이 나올 때까지 물리 계산을 매번 함께 멈추지 않는 구성 |
| CARLA 배경 렌더링 | 주행 연결에서 끔 | 실사 화면은 NuRec이 그리고 CARLA는 물리 계산에 집중 |
| NuRec | 26.4 계열의 고정 이미지, `trained` 경로 | 현재 검증한 복원 모델용 렌더링 구성 |
| Linux 실행 환경 | WSL `Ubuntu-22.04` + 컨테이너 | Windows 안에서 NVIDIA 렌더링 서버를 실행하는 공간 |
| 기본 영상 | 1280×720, 720p | 가로·세로 픽셀 수 |
| FPS 상한 | 30 | 최대 요청 목표. 실제로 안정적인 30fps를 달성했다는 뜻은 아님 |
| 필요한 객체만 유지 | `essential` | 핵심 앞차·트럭·빠른 차는 유지하고 불필요한 계산을 줄이는 구성 |
| 모델 캐시 | 1개 장면 | 메모리 부담을 줄이는 대신 장면 전환 시 다시 준비할 수 있음 |
| 정적 시점 캐시 | 기본 사용 안 함 | 현재 채택한 실행 구성 |
| 메모리 보호 | 시작 16GiB / 실행 검증 2GiB | Windows의 **남은 커밋 여유** 기준. 남은 물리 RAM만 뜻하지 않음 |

시작 화면의 `standard`는 720p와 기본 교통량이다. `balanced`는 540p와 축소 교통량을 묶는다. 4차로에서 왼쪽 빠른 차량은 기본 12대, 축소 시 8대이고 앞차와 오른쪽 대형차 3대는 유지한다.

주행 화면의 화질 선택에는 360p·540p·720p·1080p가 있다. **주행 중 해상도만 바꾸는 것과 시작 화면에서 교통량까지 묶어 바꾸는 것은 다르다.** 1080p 선택 가능 여부와 현재 PC·연구실에서의 원활한 구동 여부도 구별해야 한다. 3면 화면은 별도 성능 검증이 필요하다.

## 6. 어디를 고쳐야 설정이 바뀌나?

**`settings/*.json`은 현재 설정을 설명하고 기록하는 스냅샷이다. 그 파일만 편집해서 실행값이 바뀌지는 않는다.**

| 바꾸려는 내용 | 실제 설정·동작 위치 |
| --- | --- |
| 기본 화질·교통량 묶음 | [performance_presets.py](../performance_presets.py) |
| 4차로 속도·간격·흐름 | [highway_blockade.py](../highway_blockade.py), 로컬 `../reports/wide-highway-v2-config.json` |
| 야간 앞차 간격·흔들림 | [night_weaving.py](../night_weaving.py) |
| 안개 시작·증가 시간·농도 | [fog_scene.py](../fog_scene.py) |
| 안개 주행 시간·추종·거리 확보 | [fog_trial.py](../fog_trial.py) |
| 버튼 문구·선택지 연결 | [navigation_adapter.py](../navigation_adapter.py) |
| 결과 관찰·종료 | [action_outcome.py](../action_outcome.py) |
| 차량 위치·화면·제어 연결 | [scene_bridge.py](../scene_bridge.py) |
| Sohee 대사와 캐시 확인 | [voice_bank.py](../voice_bank.py) |
| 기록용 설정 파일 갱신 | [runtime_snapshot.py](../runtime_snapshot.py) |

설정을 수정한 뒤 관련 동작을 확인하고, 전용 Python으로 `runtime_snapshot.py`를 실행해 기록용 JSON을 갱신한다. 이미 실행 중인 Python 프로세스에는 파일 수정이 자동 반영되지 않는다. 변경할 장면을 저장·종료하고 다시 준비하는 절차가 필요하다.

세부 값은 [시나리오 스냅샷](../settings/scenarios.json), [환경 스냅샷](../settings/runtime-lock.json), [기존 설치 환경](SETUP.md)을 참고한다. 서로 다른 PC에서는 엔진·Python API·NVIDIA 이미지·원본 장면·자산·실행 옵션을 함께 맞춰야 한다.

## 7. 자주 생기는 혼동

| 질문 | 현재 구성에 맞는 설명 |
| --- | --- |
| 앞차가 흐리면 1080p로 올리면 되나? | 픽셀은 늘지만 원본에 없는 세부는 복구되지 않는다. 복원 품질·원래 촬영 거리·새 카메라 시점도 영향을 준다. |
| 트럭이 조금씩 움직이던 이유는? | 가장 가까운 기록 지점으로 시간을 고르던 문제가 있었다. 현재는 지점 사이 값을 계산해 이어 준다. 화면 전체의 GPU 렌더링 지연은 별도로 남는다. |
| 540p면 항상 더 빠른가? | 모델 계산·메모리·화면 처리·교통량도 함께 영향을 준다. 해상도 감소만으로 일정 FPS를 보장하지 않는다. |
| Sohee 대답은 매번 새로 합성하나? | 현재 NuRec 실험은 미리 준비한 실제 Qwen Sohee 음성을 재생한다. 주행 중 큰 TTS 모델을 다시 실행하지 않는다. |
| 내비 건물·차량은 YOLO 결과인가? | 차량은 연결된 시뮬레이터 위치, 건물은 캐시한 OSM 지도 윤곽이다. 영상 인식 결과와 구별한다. |
| 다른 시나리오도 모두 5분인가? | 안개는 5분으로 구성했다. 야간·4차로는 각 원본 경로와 선택 결과에 따라 종료된다. |
| 깃허브만 받으면 바로 켜지나? | 코드 외에 권한을 갖춘 원본·모델·엔진·로컬 자산·호환 실행 파일이 별도로 필요하다. |

아이폰은 같은 네트워크에서 연결 화면의 현재 QR로 접속한다. Wi-Fi가 바뀌면 PC 주소가 달라질 수 있다. 잠금 화면 알림용 HTTPS 주소가 바뀌었으면 해당 주소로 홈 화면 앱·알림 등록 상태를 다시 확인한다. 개인별 인증서·키·연결 코드는 저장소에 공유하지 않는다.

## 8. 실험 전 간단히 맞출 것

- 시나리오, 화질·교통량 프리셋, 코드 커밋을 기록한다.
- `처음으로` 후 출발 대기 상태인지 확인한다.
- 큰 주행 화면과 내비가 같은 세션에 연결됐는지 확인한다.
- 홍익 AI 열기 → 선택 → 실행 → 결과 안내를 한 번 확인한다.
