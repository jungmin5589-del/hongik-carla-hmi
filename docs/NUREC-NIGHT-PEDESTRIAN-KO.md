# NuRec 야간 보행자 양보

2026-11-03. 기존 CARLA 보행자 조건과 별도로 선택하는 하이브리드 시제품입니다.

## 화면과 행동

NuRec 원본의 **실제 야간 도로 배경**을 사용합니다. 낮 영상을 어둡게 바꾼 것이 아닙니다.
다만 가까운 보행자와 흰색 횡단 구간은 우리가 추가한 실험 요소입니다. 실제 원본 도로에
그 횡단보도나 사람이 있었다는 뜻은 아닙니다. 원본의 차량을 가까이 옮기지 않습니다.

1. 차량이 약 15km/h 이하로 횡단 구간에 접근하며 감속합니다.
2. 보행자는 반 걸음 내딛었다 물러나며 차량 쪽을 보고 손짓합니다. 차량은 정차합니다.
3. 왼쪽 아래 홍익 AI 버튼이 새 상황을 알립니다. 누르면 기존 Sohee 음성으로 설명하고
   **클락션 / 하이빔 / 직접 대응 / 기다리기**를 세로로 제시합니다. ETA는 숨깁니다.
4. 선택 후 실행해야 행동이 반영됩니다. 직접 대응은 실제 음성을 해석하지 않으며,
   승객이 말한 뒤 **대응 완료**를 눌러야 다음 반응으로 진행합니다.
5. 보행자가 실제로 횡단 구간을 벗어나고 2초간 확인한 뒤 차량이 다시 출발합니다.
   결과를 보여준 후 정차하고 내비에 종료 안내를 남깁니다.

아무것도 선택하지 않아도 약 75초 대기 후 횡단합니다. 선택하면 약 8초 반응 대기 후
횡단합니다. 대기·횡단·안전 확인 중에는 차량을 정차시킵니다. 이는 정해진 시나리오 반응이며,
보행자의 의도나 손짓을 AI가 인식한 결과는 아닙니다.

## 실행

기존 NuRec 선택 화면 `http://127.0.0.1:8775/`에서 **05 야간 보행자 양보**를 고릅니다.
내비에서 출발을 누르고, 큰 주행 화면은 설정의 **주행 화면 열기**로 엽니다.
첫 모델 준비에는 수 분이 걸릴 수 있습니다. 현재 PC에서는 우선 540p를 권장합니다.

```powershell
python launch_live.py --profile night_pedestrian --quality balanced
```

현재 권한이 확인된 야간 원본·NVIDIA 런타임·CARLA 0.9.16 설치가 필요합니다. 저장소만
복제해서 원본을 다운로드하거나 모델을 실행할 수 있는 것은 아닙니다. 추가 Python 의존성:

```powershell
python -m pip install --no-deps opencv-python-headless==4.11.0.86
```

기존 `walker.pedestrian.0001` 걷기 캐시를 사용합니다. 없으면 기본 CARLA 걷기를 사용하고
멈춘 동안 손짓합니다. 캐시 생성은 `AMBIENCE-PEDESTRIAN-KO.md`를 참고합니다.

## 합성 방식과 한계

`nurec_pedestrian.py`는 기존 보행자 상태와 내비 선택지를 연결합니다.
`hybrid_pedestrian.py`는 CARLA의 RGB·인스턴스 ID·깊이 카메라를 사용합니다.
세 이미지의 CARLA 프레임 번호가 모두 같을 때만 사용하며, 그때의 실제 카메라 자세로
NuRec 배경을 요청합니다. 렌즈 보정값에 맞춰 사람을 재투영하고 같은 NuRec 요청의 거리
정보로 가림을 처리합니다. 임의의 화면 좌표에 사람 그림을 고정해 붙이지 않습니다.

정차 중 카메라 위치·회전·원본 시간이 매우 작은 허용 오차 안에서 같을 때만 배경을
재사용합니다. 보행자는 계속 CARLA로 갱신합니다. 배경의 원본 교통 시간은 이전 조건과
동일하게 차량의 경로 진행에 연결되므로, 정차하면 원본 교통도 멈춥니다.

야간 노출·색감과 하이빔의 배경 밝기 변화는 근사입니다. 원본의 구워진 조명을 완전히
다시 계산하지 않습니다. 보행자는 CARLA의 게임 모델이므로 실사 사람과 동일하지 않고,
지면 접촉 그림자·주변 조명의 완전한 일치도 구현하지 않았습니다. 원본의 광원 번짐과
재구성 흐림도 유지됩니다. 긴 구간이나 정교한 연구 자극으로 쓰기 전 육안 검토가 필요합니다.

다른 NuRec 조건은 기존 physics-only 기본값을 유지합니다. 이 조건에서만 CARLA 카메라
렌더링을 켭니다. DX12·비동기 물리·16GiB 시작/2GiB 검증 메모리 기준은 유지합니다.
최신 CARLA UE5의 공식 하이브리드 기능을 설치한 것이 아니라, 현재 고정된 0.9.16에
별도 연결한 구현입니다.

## 확인한 범위

실제 CARLA + NuRec 540p에서 클락션과 하이빔을 각각 실행해
접근 → 대기 → 횡단 → 안전 확인 → 재출발 → 종료까지 확인했습니다.
두 실행 모두 보행자 충돌 0회, 실제 망설임 이동 폭 약 0.52m였습니다.
추가로 실제 내비 브라우저에서 설명·직접 대응 선택·실행·대응 완료를 누른 뒤
횡단·재출발·종료까지 확인했으며 충돌은 없었습니다. 종료 후에는 렌더링을 대기 주기로 줄입니다.
하이빔은 주행 스트림에 on/off/on/off가 전달돼야 각 점멸 단계를 종료합니다.

보행자 부분만 처리하도록 계산 범위를 줄인 뒤 이 PC의 대기 구간에서 약 **16 FPS**를
관측했습니다. 접근·재출발 중에는 배경을 계속 계산하므로 대략 **3~4 FPS** 수준이었습니다.
실제 프레임 간격이며 30 FPS를 달성했다는 뜻이 아닙니다. 30은 기존 상한 목표입니다.
테스트 장면의 수치이며 참가자 연구 결과나 모든 PC의 성능 보장은 아닙니다.

```powershell
python -m unittest test_nurec_pedestrian test_pedestrian_yield test_navigation_adapter
python validate_nurec_pedestrian.py --action horn
python validate_nurec_pedestrian.py --action highbeam
```

실행 검증기는 현재 선택한 장면을 초기화하고 실제 대응을 실행합니다. 자세한 상태·영상은
로컬 `validation/`와 `runs/`에만 보관하며 Git에는 포함하지 않습니다.
