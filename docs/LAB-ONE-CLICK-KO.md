# SSD를 가져가서 실행하기

## 가져갈 폴더와 클릭할 파일

SSD의 `Hongik-CARLA-Lab-20261107` 폴더 전체를 사용합니다.
가능하면 연구실 내장 SSD의 새 폴더로 통째로 복사합니다. 예전 연구실 설치 위에 덮어쓰지 않습니다.
맨 위 **`00_START_LAB.bat`**을 실행합니다.
기존 `live/52_LAB_START.bat`, 새 `live/59_LAB_ONE_CLICK.bat`도 같은 시작 절차입니다.
SSD 드라이브 최상위에 둔 **`START_HONGIK_LAB.bat`**도 같은 파일을 상대 경로로 엽니다.
SSD 드라이브 문자가 D에서 다른 문자로 바뀌어도 폴더 이름이 같으면 사용할 수 있습니다.

1. 처음에는 동봉 엔진을 별도로 준비합니다. 이미 준비된 엔진은 다시 풀지 않습니다.
2. Python·엔진·음악·한국어/영어/중국어 음성·환경음·보행 자료를 검사합니다.
3. 기존 5760×1080 Surround 배치를 확인하고 별도 CARLA 0.9.16을 RPC 2026에 준비합니다.
4. 기존 내비·참가자 등록 화면과 아이패드 QR을 함께 엽니다.
5. 참가자 등록 → 언어/조건/시나리오 선택 → 준비 완료 후 출발합니다.
6. 좌·정면·우 영상은 같은 차량의 세 카메라로 표시합니다. 기본은 각 면 720p입니다.

연구실의 기존 다른 CARLA를 먼저 정상 종료해야 합니다. 실행기는 타인의 프로그램을 강제로
종료하지 않습니다. 기존 NVIDIA Surround·방화벽·보안 설정도 자동으로 바꾸지 않습니다.
엔진 압축을 처음 풀 때는 내장 SSD에 추가 여유 공간이 필요합니다.

노트북의 작은 세 시야 미리보기는 `live/59_LAB_ONE_CLICK.bat --preview`, 실행 없는 자원 확인은
`live/59_LAB_ONE_CLICK.bat --check`입니다. 오류가 나면 콘솔을 닫지 않고 남겨줍니다.

## 아이패드

PC와 아이패드를 기기 간 통신이 허용되는 같은 네트워크에 둡니다.
시작 화면 오른쪽 QR을 Safari로 스캔하면 **기존 Three.js 전체 내비**가 열립니다.
주소는 그날 연구실 PC IP로 자동 표시되며, 예전 노트북 IP를 입력하지 않습니다.
직접 입력할 때는 `http://연구실PC의IP:8776/m/navigation`과 표시된 6자리 코드를 사용합니다.

QR 화면은 `http://127.0.0.1:8774/lab`, 별도 연결 화면은
`http://127.0.0.1:8776/connect?view=tablet`입니다. 연결 코드 만료 시 새 코드를 표시하고,
연결 서버가 응답하지 않으면 이전 QR과 주소를 숨깁니다. 새 기기 연결은 기존 연결을 대체합니다.
잠금 화면 시스템 알림은 새 PC의 HTTPS·인증서·홈 화면 앱·알림 허용이 별도로 필요합니다.
참가자 기록 DB와 Drive 로그인도 각 PC에서 별도 관리합니다. 개인 인증정보를 SSD에 복제하지 않습니다.

## MotionHouse·WebSocket: 현장에서 마저 확인할 부분

현재 파일은 3면 영상·내비·장면 음성을 자동 준비합니다. **6DoF 물리 모션을 보내거나 장치를
활성화하지 않습니다.** MotionHouse 프로그램의 실제 설치 경로와 사용자가 지난번 성공한
연결 스크립트가 아직 없으므로, 이를 실행하는 기능까지 완성됐다고 표현하지 않습니다.

사용자가 제공한 원본 ZIP을 다시 분석한 결과는 다음과 같습니다.
원본 사본은 SSD 폴더의 `reference/LAB_ORIGINAL_VLA_XAI_v0.9.1.zip`에 별도로 보관합니다.
연구실에서 Codex로 대조하기 위한 자료이며, 기존 수집기를 자동 실행하는 파일이 아닙니다.

| 원본 위치 | 확인한 내용 |
|---|---|
| `carla/data-server/collector/carla_collector.py` | `run_collector(world=None, vehicle=None, background=False)`가 CARLA 데이터를 배분 |
| `carla/data-server/sender/udp_sender.py` | MotionHouse용 6축 UDP, 포트 10000, 별도 필터·속도 제한·출력 루프 |
| `carla/data-server/sender/websocket_sender.py` | 실제 기본 포트는 `WS_PORT` 또는 8766. 예전 설명에는 8765도 남아 있음 |
| 기존 연구실 실행 환경 | CARLA 0.9.15 / Python 3.10 |
| 이번 별도 환경 | CARLA 0.9.16 / Python 3.12, RPC 2026 / 내비 8774 / 모바일 8776·8777 |

따라서 예전 수집기가 기본 RPC 2000에 연결되거나 예전 ego를 읽으면 우리 시나리오와 다른
신호를 보낼 수 있습니다. 현재 앱의 `/api/state`에서 ego ID·월드 위치·세션을 확인하고,
수집기에서도 **같은 월드와 같은 차량**을 사용하도록 현장에서 대조해야 합니다.
시나리오를 바꿀 때 ego ID가 바뀌므로 이전 차량을 계속 읽지 않는지도 확인합니다.
자료의 다른 시나리오용 모션 필터 숫자를 새 상황에 그대로 복사하지 않았습니다.

연구실에서 Codex에 이 대화를 열고 다음을 보여줍니다.

- MotionHouse 프로그램의 정확한 이름, 실행 파일 위치와 평소 실행 순서
- 지난번 성공한 WebSocket BAT/스크립트, 실행하는 Python 환경
- 원래 연결 포트와 ego 선택 방식, 장비 중립·시작·정지 절차

먼저 `live/55_LAB_CONNECTION_CHECK.bat`으로 읽기 전용 연결 보고서를 남깁니다.
이 파일은 모션·차량 명령을 보내지 않습니다. 그다음 프로그램 실행과 데이터 연결을
검증하고, 담당자가 중립·정지 절차를 확인한 상태에서 물리 모션을 별도로 점검합니다.

## 확인 범위

이 시작 절차와 자원은 로컬/휴대 환경에서 검사합니다. 연구실 실제 GPU·3면 이음새·음량,
현장 Wi-Fi 접근, MotionHouse 구동은 현장 확인이 남습니다. 30fps는 목표 상한이며 보장치가 아닙니다.

2026-11-10 SSD의 **휴대용 Python·동봉 엔진**으로 `lab_one_click.py --preview` 실행을
확인했습니다. 자원 점검 오류 0건, 휴대용 Native 관련 검사 26개 통과, 실제 CARLA 카풀 장면의
좌·정면·우 같은 프레임 묶음과 일시정지 상태를 확인했습니다. 브라우저에서는 기존 참가자 등록,
중국어 선택, 실제 게이트웨이 QR, QR 접기, 연결 단절 시 오래된 QR 숨김과 복구를 확인했습니다.
이 점검에서는 주행을 시작하거나 물리 모션을 활성화하지 않았습니다.
NuRec 원본 보고서가 필요한 별도 렌더러 검사는 이 Native 전용 휴대 폴더의 검사 대상이 아닙니다.
로컬 점검으로 생성된 모바일 인증서·연결 정보와 실행 로그는 가져갈 폴더에서 분리합니다.
