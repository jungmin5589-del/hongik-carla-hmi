# 설명을 듣고 대응을 선택하는 세 가지 상황

50번 CARLA 시작 화면에서 기존 고속도로 세 조건과 새 상호작용 세 조건을 선택한다.
새 조건은 ④ 보행자 양보, ⑤ 카풀 대기 중 외부인 접근, ⑥ 반복되는 이상음이다.
NuRec 원본, 모델, 새로운 3D 에셋 다운로드는 필요하지 않다.

## 공통 인터페이스

상황 발생 → 홍익 AI 버튼 알림 → 클릭 → Sohee 설명 → 세로 선택지 → 실행 확인 →
실제 반응과 결과 관찰 → 종료 안내 순서다. 설명을 다 들으면 선택지가 나타난다.
텍스트만 읽거나 설명을 건너뛰려면 **대응 방법 보기**를 누른다.
네 선택지는 같은 크기·색이며 단계 번호와 추천 표시를 두지 않는다.
이 세 조건에서는 뒤쪽 내비를 포함해 ETA·예상 소요·남은 경로 수치를 숨긴다.
확인창에도 행동별 예상 시간이나 도착 시간 차이를 표시하지 않는다.

X는 설명/선택창을 닫는다. 실제로 실행한 행동을 소급 취소하는 버튼은 아니다.
알림만 보거나 선택하지 않은 경우도 로그로 구분한다. UI 노출/누른 시각은 시선 측정이 아니다.

## 보행자 양보

| 선택 | 실행 |
|---|---|
| 클락션 | 짧은 경적 소리와 보행자 반응. 차량은 정차 유지. |
| 하이빔 | 실제 CARLA 상향등 두 번 점멸과 내비 표시. 차량은 정차 유지. |
| 직접 대응 | 승객이 보행자에게 직접 말한 뒤 **대응 완료**를 누른다. 음성을 인식하거나 전사하지 않는다. |
| 기다리기 | 추가 자극 없이 보행자의 움직임을 기다린다. |

보행자는 횡단보도에 조금 진입해 손짓한다. 어떤 선택도 차량을 강제로 출발시키지 않는다.
실제 보행자 위치가 횡단 구간을 벗어난 것을 확인하고 차량이 다시 출발한다.
손짓과 반응은 정해진 연출이며 영상 기반 제스처 인식이 아니다.
직접 대응을 실행한 경우에는 대응 완료를 누르거나 시나리오를 초기화할 때까지 기다린다.

## 카풀 대기 중 외부인 접근

실제 맵의 주차 구역에 정차한다. 바깥 목소리와 발소리가 들리고 사람이 다가온다.
AI는 '고성과 접근', '동승자인지 미확인'을 설명하며 취했는지나 위험 인물인지 판정하지 않는다.

| 선택 | 실행 |
|---|---|
| 외부 안내로 용건 확인하기 | 안내 음성을 전달하고 상대가 물러나는 반응을 확인한다. |
| 관제 지원 요청하기 | 정해진 모의 관제 응답과 상대의 반응을 보여준다. |
| 다른 대기 장소 요청하기 | 같은 주차 구역 안에서 약 6m 이동해 정차한다. |
| 현재 대기 유지하기 | 문이 닫힌 상태로 주변을 확인한다. |

외부인 목소리는 Qwen Aiden으로 만든 합성 음성이다. 실제 취객 녹음이 아니다.
카풀 외부인은 어두운 버건디 상의와 짙은 바지의 기본 캐릭터(0034)를 사용한다.
다가온 뒤 차 앞쪽과 조수석 옆을 오가며 안쪽을 살피고, 실제 문 근처에 도착해
멈춘 경우에만 오른팔로 두드리는 동작을 한다. 이동 중에는 기본 보행 애니메이션을 쓴다.
접근·기웃거림·문 두드림은 정해진 반복 연출이며 외모로 위험이나 음주 여부를 판정하지 않는다.
외부인은 택시로 착각하고 승차 거부에 시비를 거는 취객 역할로 연출한다. 시작 후 고정 타이머로
말하지 않는다. 실제 인물이 조수석 옆 목표점 0.38m 안에 멈추고(속도0.15m/s 미만),
차량을 바라보는 방향 오차18도 이내가 약0.65초 유지되면 첫 대사를 시작한다.
첫 대사는 '야, 택시! 너 지금 나 무시하냐?'이며 이후 '문 열라고! 택시! 야!' 등으로 이어진다.
그 시점을 기준으로 0·8·18·30·44·58초에 서로 다른 여섯 대사를 한 번씩만 제시한다.
홍익 AI 알림도 첫 대사 시작에 맞추며, 선택하지 않은 기본 대기 시간은 그 알림부터75초다.
문 두드림은 첫 대사를 시작한 뒤3초가 지나고 실제 문 근처에 있는 경우에 시작한다.
같은 두 문장을 순환하지 않는다. AI 설명 중에는 외부 대사를 중지하고 아직 유효한 다음 대사만
기다리게 한다. 창을 숨긴 동안 놓쳤거나 유효 시간이 지난 대사를 몰아서 재생하지 않는다.
외부인 대사만 Qwen3-TTS 1.7B CustomVoice Aiden의 감정 지시를 사용해 공격적인 고성과
거친 호흡, 재촉하는 말투로 사전 합성한다. AI의 기존0.6B Sohee 음성은 바꾸지 않는다.
대사는 저장된 합성 음성이며 실제 취객 녹음이나 실시간 대화 생성이 아니다. 배우의 음주 연기나
억양의 자연스러움을 검증한 것은 아니다. 한 번의 문 두드림은
불규칙한 세 타격이며 실제 인물의 문 근접 상태와 손동작 시계를 기준으로 재생한다.
일시정지·창 숨김 중 놓친 타격은 복귀 시 몰아서 재생하지 않는다. AI 설명 중에는 타격음을 낮춘다.
인물이 물러나면 고성과 타격을 멈춘다. 위치 변경을 실행한 경우에는 바로 물러나도록 한다.
조수석 쪽 움직임이 보이도록 이 조건의 전방 카메라만 오른쪽 25도, 화각 100도로 조정한다.
AI는 Qwen Sohee를 유지한다. 발소리는 절차적으로 생성한 효과음이다.
오른쪽에서 들리는 위치와 음색 필터로 차량 밖의 소리를 표현하지만 헤드 트래킹 기반
공간 음향이나 실제 외부 스피커 장치가 아니다. 문 닫힘/잠금은 실험 상태 표현이며
실차의 잠금 하드웨어를 제어하거나 검증하는 기능이 아니다.

## 주행 중 반복되는 이상음

주행 중 하부 덜컹거림을 합성 효과음으로 재생한다. 실제 CARLA 차량 고장은 발생시키지 않는다.

| 선택 | 실행 |
|---|---|
| 차량 상태 점검 요청하기 | 모의 점검 결과를 제공하며 원인을 확정하지 않았음을 알린다. |
| 관제 지원 요청하기 | 모의 관제에 이상음을 전달하고 감속 주행한다. |
| 안전한 장소에 정차 요청하기 | 맵에서 확인한 비어 있는 갓길로 이동해 정차한다. |
| 현재 주행 유지하기 | 이상음이 있는 동안 차량 상태를 살피며 주행한다. |

갓길 후보는 차량 폭을 포함한 위치가 Shoulder/Parking인지 확인한다. 실제 차량 위치와
속도로 결과를 판정한다. 공간을 확인하지 못하면 갓길 정차 완료로 표시하지 않는다.
관제와 점검은 실제 상담원 연결이나 기계 고장 진단이 아니다.

## 소리와 데이터

PC 내비에서 주행 시작을 눌러 브라우저 환경음을 활성화한다. AI 설명 중에는 이상음을
줄이고 외부인의 음성을 멈춰 겹침을 줄인다. 일시정지·페이지 숨김·종료 시 환경음을 멈춘다.
여러 PC 내비 탭이 같은 환경음을 중복 재생하지 않도록 재생 소유권을 둔다.
새 음성은 `prepare_city_audio.py`로 한 번 만들고 `../cache/city-audio/`에 보관한다.
공격적인 외부 대사는 별도로 준비한다. 기존 TTS 환경에서 `prepare_exterior_voice.py --download`로
공식1.7B 가중치 약4.21GiB를 D의캐시에 한 번 받은 뒤, CARLA를 멈추고
`prepare_exterior_voice.py`를 실행한다. 생성 시에만6GiB commit 여유와4.5GiB GPU 여유를 요구한다.
주행/내비 프로세스는1.7B 모델을 로드하거나 내려받지 않는다. 준비 과정은 CPU/GPU를 쓰므로
주행과 병행하지 않는다. 모델 원본과 새 WAV는 Git에 넣지 않는다.
주행 프로세스는 합성 모델을 로드하지 않는다. WAV·매니페스트·기록은 Git에 포함하지 않는다.
기존 아이폰 게이트웨이/권한 설정은 변경하지 않았다. 새 단계와 직접 대응 완료는 PC 내비에서 검증한다.

## 개발 검증

`python -m unittest test_native_carla test_pedestrian_yield test_city_scenarios test_navigation_adapter test_action_outcome test_presentation test_repo_safety`

`node test_hongik_panel.cjs`

`node test_exterior_sound.cjs` — 짧은 문 타격음의 샘플레이트별 유한성·클리핑·감쇠 검사.

`node test_taxi_dialogue.cjs` — 격리된 QA 브라우저에서 약80초 동안 여섯 대사가 순서대로
한 번씩 재생되는지 검사한다. 실제 스피커 음질·취객 연기·참가자 반응의 평가는 아니다.

실제 CARLA 검사: `python validate_city_cases.py <yield|carpool|rattle> <study_...|none>`.
별도 빈 프로필의 headless 브라우저 검사: `node test_city_browser.cjs <profile> <action>`.
화면·오디오 재생·실제 움직임의 개발 QA를 참가자 효과, 실차 검증이나 연구실 3면 성능과 구별한다.
도착 시간을 숨겨도 행동 효과와 대기 길이의 차이가 선호에 영향을 줄 수 있으므로 참가자 연구에서
순서·반복·시간 조건을 별도로 검토해야 한다. 모든 선택의 체험 시간이 같다고 주장하지 않는다.
