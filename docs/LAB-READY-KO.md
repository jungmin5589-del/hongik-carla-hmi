# 연구실 3면 CARLA 준비

2026-11-07. 연구실 원본 설정을 확인해 준비한 별도 실행 폴더입니다. 현장 장비에서 검증을 마쳤다는 뜻은 아닙니다.

## 도착해서 실행하는 순서

2026-11-10 추가: 폴더 맨 위 **`00_START_LAB.bat`** 한 번으로 첫 준비·자원 점검·앱 실행을
이어갑니다. 기존 `live/52_LAB_START.bat`과 새 `live/59_LAB_ONE_CLICK.bat`도 같은 경로입니다.
엔진을 처음 푸는 시간은 필요합니다. 이미 준비된 엔진은 다시 풀지 않습니다.
기존 내비는 그대로 열리고 오른쪽에 현재 Wi-Fi의 **전체 아이패드 내비 QR**을 표시합니다.
코드 만료·Wi-Fi 변경 시 화면을 갱신하며, QR을 접거나 내비만 전체 화면으로 열 수 있습니다.
참가자 등록·관리자 기록·한국어/영어/중국어 화면과 사전 생성 음성도 함께 가져갑니다.
자세한 현장 절차와 남은 모션 연결 항목은 [원클릭 실행 안내](LAB-ONE-CLICK-KO.md)에 있습니다.

1. SSD의 `Hongik-CARLA-Lab-20261107` 폴더를 **연구실 내장 SSD**로 통째로 복사합니다. `live`, `python`, `CARLA_0.9.16.zip`, `cache`를 함께 옮깁니다. 엔진을 풀 공간으로 추가 20GiB 이상을 확보하고, 기존 CARLA 폴더에는 덮어쓰지 않습니다.
2. 기존 연구실 주행 프로그램을 정상 종료합니다. 다른 CARLA가 실행 중이면 이 실행기는 임의로 종료하거나 그 월드를 바꾸지 않습니다.
3. Windows의 기존 NVIDIA Surround 화면이 **5760×1080**인지 확인합니다.
4. 폴더 맨 위 `00_START_LAB.bat`을 실행합니다. 처음에는 별도 엔진 준비와 점검을 자동으로 먼저 합니다. 수동 준비 파일 `live/51_LAB_SETUP.bat`도 유지합니다. 첫 압축 해제 시간은 필요하지만 Python 설치나 모델 다운로드는 필요 없습니다.
5. 조작용 모니터에서 기존 내비의 시나리오를 선택합니다. 준비가 끝나면 좌·정면·우 화면이 서라운드에 나타납니다. 내비는 조작 모니터에 두고 출발을 누릅니다. 소리는 이 내비 브라우저에서 재생됩니다.
6. 처음에는 720p로 확인합니다. 출력은 5760×1080이며 각 면을 1280×720에서 확대합니다. 내비의 화질을 1080p로 바꾸면 세 카메라가 각각 1920×1080으로 렌더링합니다. 부하가 크면 540p로 낮춥니다. 세 면을 함께 검증하기 전에는 30fps가 안정적이라고 판단하지 않습니다.

모니터 위치가 바뀌어도 5760×1080 화면을 감지해서 배치합니다. 찾지 못하면 화면 밖으로 창을 열지 않고 중단합니다. 노트북에서 작게 세 시야를 보려면 `53_LAB_PREVIEW.bat`, 읽기 전용 점검은 `54_LAB_CHECK.bat`을 사용합니다. 미리보기는 실제 3면 장비 검증을 대신하지 않습니다.

내비 한국어·영어 선택과 음악 플레이어는 유지합니다. 취객은 **이전 태양 고도 12°의 낮은 햇빛 환경**으로 복구했고, **뒤에서 접근 → 목소리가 먼저 들림 → 옆 창에서 보임 → 문 두드림**의 연출은 유지했습니다. 216° 시야의 끝에 인물이 잘리지 않도록 최종 도착 위치는 앞쪽 옆 창으로 맞췄습니다. 졸음운전의 야간 조건은 별도로 남겨뒀습니다.

취객 조건은 Tesla 차체의 지붕에 얼굴이 가려지지 않도록 기존 단일 화면의 높이를 반영해 세 시점 공통 눈 위치를 (0.9,-0.35,1.6)m로 보정했습니다. 다른 조건은 원본 눈 위치를 사용합니다. 화각·방향과 달리 차량 모델에 따라 눈 위치는 현장에서 좌석 기준으로 확인해야 합니다.

## 왜 우리 엔진을 따로 가져가나

연구실 자료의 0.9.15와 현재 개발·검증에 사용한 0.9.16은 같지 않습니다. 실제 0.9.15 Python 클라이언트를 별도 설치해 조사했더니 현재 취객 연출이 사용하는 `get_bone_names`, `get_bone_world_transforms`가 없습니다. 0.9.15 공식 Blueprint 목록에도 현재 사용하는 `vehicle.carlamotors.european_hgv`가 없습니다. 버전 번호만 낮추면 같은 시나리오가 된다고 보장할 수 없습니다.

따라서 동봉된 **별도 CARLA 0.9.16 + Python 3.12.10**으로 현재 시나리오를 유지하고, **화면 설정은 연구실 값**을 적용합니다. 기존 0.9.15·Python 3.10·연구실 HMI·모션 프로그램은 설치하거나 수정하지 않습니다. 전용 RPC는 2026, 내비는 8774를 사용합니다. 기존 원본의 WebSocket 8766 / UDP 10000 파이프라인에 자동 연결하지 않습니다.

이번 실행기는 **3면 영상·내비·장면 음성**용입니다. 6축 모션 명령을 보내지 않습니다. 물리 모션 연동은 연구실 담당자와 장비의 기존 보정·중립·정지 절차를 확인하고 별도 검증해야 합니다. 자료에 적힌 다른 시나리오의 필터 숫자를 우리 장면에 그대로 적용하지 않았습니다.

## 폴더와 가져가는 범위

- `CARLA_0.9.16.zip`: 별도 실행 엔진·기본 지도. 51번이 이를 `CARLA_0.9.16` 폴더로 풉니다. 편집기와 NuRec는 필요하지 않습니다.
- `python`: 경로를 옮겨도 쓰는 전용 실행 환경. 전역 Python을 바꾸지 않습니다.
- `live`: 기존 내비, 일곱 상황, 3면 실행기와 점검 스크립트.
- `cache`: 한국어/영어 사전 생성 음성, 보행 주기, 실제 주행음, 효과음과 기존 음악.
- `SOURCE-MANIFEST.json`: 전달 소스의 SHA-256.

개인 휴대폰 연결 쿠키, 구독 정보, 인증서·개인 키, Git 자격증명과 NuRec 모델은 넣지 않습니다. 새 PC에서 모바일 연결이 필요하면 새 QR로 연결합니다. 기존 노트북 인증서를 새 PC용이라고 복제하지 않습니다. 이 폴더는 사용자의 연구실 시연용이며 엔진·음악·오디오를 포함하므로 공개 GitHub에 업로드하지 않습니다. 원본 출처·라이선스 파일은 유지합니다.

## 구현과 검증 구분

내비에서 출발을 한 번 클릭해 소리를 활성화합니다. 차단되면 **장면 소리 켜기**를 누릅니다. 활성화한 내비는 3면 주행창 뒤에서도 취객 대사와 AI 설명을 재생합니다. 실제 신발 접촉음은 이동 중에만 작게 재생하며, 출처와 검증 범위는 `live/docs/SCENE-AUDIO-KO.md`에 있습니다.

세 카메라는 같은 차량에 붙고, 같은 CARLA 프레임 번호의 세 영상이 모두 준비됐을 때만 한 묶음으로 표시합니다. 누락 프레임을 무한히 쌓지 않습니다. 정면 카메라를 내비와 공유하므로 같은 주행을 위해 네 번째 카메라를 추가하지 않습니다. 비동기 물리·DX12 기본 설정, 16GiB 시작 / 2GiB 검증 여유 기준은 유지합니다.

낙하물 확인의 확대는 내비의 정면 확인 창을 디지털 확대합니다. 주행용 세 화면의 화각과 이음새를 갑자기 바꾸지 않습니다. 기존 단일 화면 모드의 카메라 확대는 유지합니다.

로컬 검증과 현장 검증은 구분합니다. 자료에 적힌 화면 배치·버전은 확인했지만 연구실 3면의 실제 이음새·색감·음량·장시간 FPS는 현장에서 확인해야 합니다. 이번 준비 결과의 실제 구동 검사 범위는 GitHub 변경 기록과 로컬 검증 기록에 남깁니다.

로컬 실제 CARLA에서는 일곱 상황 각각의 3면 준비·같은 프레임 묶음과, 취객의 뒤쪽 외침·옆 창 도착·두드림·이동 대응을 검사했습니다. 전달용 Python은 사용자 PC의 별도 라이브러리 경로를 읽지 않도록 분리했습니다. 엔진 압축의 전체 CRC 검사는 통과했습니다. 엔진을 새 연구실 PC에 풀어 구동하는 단계와 실제 3면 장비 보정은 현장에서 확인합니다.
