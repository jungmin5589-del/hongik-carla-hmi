# 내일 연구실 UX 점검 순서

## 1. 가져갈 것과 첫 실행

- 외장 SSD의 `Hongik-CARLA-Lab-20261107` 폴더 전체. 이름의 날짜와 무관하게 최신 코드가 들어 있다.
- 가능하면 연구실 내장 SSD의 **새 폴더**로 전체 복사한다. 기존에 잘 작동한 연구실 설치·WebSocket 수정본에 덮어쓰지 않는다.
- `00_START_LAB.bat` 실행. SSD에서 바로 실행할 때는 최상위 `START_HONGIK_LAB.bat`도 같은 진입점이다.
- 처음에는 동봉 CARLA 엔진을 풀 시간이 필요하다. 폴더 전체가 필요하며 GitHub 소스만으로 엔진·음성·음악까지 준비되지는 않는다.
- 실행 자원 검사만: `live/59_LAB_ONE_CLICK.bat --check`.
- 기존 CARLA가 실행 중이면 담당자와 정상 종료 순서를 확인한다. 실행기는 다른 사용자의 프로그램을 강제 종료하지 않는다.

## 2. 참가자 없이 먼저 화면·음성 확인

- 연구실 5760×1080 Surround 배치에서 좌·정면·우 시야와 이음새를 확인한다. 기본 렌더는 각 면1280×720이며 30fps 보장은 아니다.
- 화면과 내비가 같은 우리 차량을 가리키는지, 출발 준비 중 차가 이동하거나 틀어지지 않는지 확인한다.
- 한국어를 기본으로 두고 설명·선택 후 응답·환경음·경적이 겹치거나 빠지지 않는지 확인한다. 영어/중국어는 필요한 참가 언어를 추가 점검한다.
- 출발 메모리 기준16GiB, 검증 중2GiB 기준을 우회하지 않는다. 부족하면 작업을 저장하고 불필요한 앱을 닫는다.

## 3. 아이패드

- PC와 아이패드를 기기 간 통신이 가능한 같은 네트워크에 연결한다.
- PC 시작 화면의 **그날 새 QR**을 Safari로 열어 전체 내비를 확인한다. 지난 노트북 IP나 만료 코드를 재사용하지 않는다.
- 직접 주소: `http://연구실PC-IP:8776/m/navigation`.
- 아이패드에서 버튼 실행→PC 차량 동작→아이패드 결과 안내까지 왕복 확인한다.
- 내일 UX 테스트는 우선 앱을 열어두고 진행한다. 잠금 알림은 새 PC의 별도 인증서·HTTPS·홈 화면 앱·허용 상태를 따로 확인해야 한다.

## 4. B 조건의 핵심6개 점검

각 장면에서 `상황 발생→AI 버튼 알림→설명→세로 선택지→선택 확인→실행→실제 결과→종료→시나리오 선택 복귀`를 확인한다. 시작 전에 참가자 이름/ID와 언어를 확인한다. 개발 시험용 ID와 실제 참가자 ID를 구분한다.

| 장면 | 대표 확인 |
|---|---|
| 4차로 정체 | 가까운 앞차와 트럭 두 줄, 왼쪽 고속 흐름. 첫 선택지 클락션과 긴 경적. 정차 요청은 감속 주행 후 갓길 이동·최종 정지 |
| 야간 졸음운전 | 우리 차 차로 유지, 앞차 흔들림, 클락션 또는 거리 벌리기 결과 |
| 짙은 안개 |10초 뒤 시작해5초 동안 짙어짐, 감속 선택, 중단 후 정지·종료 복귀 |
| 보행자 양보 | 접근·머뭇거림, 양보 안내, 보행자가 벗어난 뒤의 차량 반응 |
| 카풀 대기 | 뒤쪽 접근 소리→옆창 등장→대사·노크, 이동 선택 결과 |
| 반복 이상음 | 주행음과 이상음 구분, 점검·감속 선택 후 피드백 |

낙하물은 추가 장면으로 따로 확인한다. 위 표는 모든 선택지 검증이 이미 끝났다는 뜻이 아니다. X·실행 전 취소·실행 후 중단도 확인한다.

## 5. 실험 기록

- 테스트 ID로 한 번 선택한 뒤 관리자 페이지에서 시나리오·선택지·출발/상황 발생 이후 시간·실행·결과가 보이는지 확인한다.
- PC 로컬 기록이 먼저 저장된다. 연구실 PC의 Drive 앱 로그인·새 비공개 기록 폴더 연동은 별도 확인한다. 노트북의 개인 인증정보를 복사하지 않는다.
- 동기화가 안 되어도 로컬 기록을 보존한다. 공개 GitHub에는 참가자 DB·세부 로그·인증정보를 올리지 않는다.

## 6. 연구실 WebSocket·모션 장비는 별도 현장 확인

- 지난번 성공한 BAT·수정 코드·Python 환경·MH 프로그램의 실행 파일과 순서를 먼저 확보/백업한다.
- `live/55_LAB_CONNECTION_CHECK.bat`으로 읽기 전용 연결 보고서를 남긴다.
- 원본은 WebSocket 기본8766, MotionHouse UDP10000. 옛 설명의8765와 혼동하지 않는다.
- 현재 별도 앱은 CARLA0.9.16/RPC2026, 원본은0.9.15/RPC2000이다. 수집기가 **같은 월드와 ego ID**를 읽는지, 시나리오 전환 후 새 ego로 갱신되는지 확인한다.
- WebSocket 입력 기록과 실제 주행 명령 실행은 별도 기능이다. 실제 CARLA 동작과 결과 안내까지 확인한다.
- 현재 통합 시작 파일은 물리 모션 명령을 보내지 않는다. 담당자와 기존 장비 시작·중립·정지 절차를 확인하고 연결한다.

## 지금 PC에서 확인한 범위

최종 준비 시점 소스 기준331개 파일의 SSD 해시·원본 일치, 휴대 환경 실행 자원 오류0건, 실행기·설정·정렬·참가자 기록 관련 자동검사42개 통과. 현재 로컬 CARLA의 ego와 내비 위치가 일치하고 모바일 게이트웨이가 응답했다. 정체의 새 정차·클락션은 앞선 실제 로컬 주행에서 확인했다.

연구실 물리3면·모션·그곳 Wi-Fi·실제 아이패드 음량·새PC Drive 연동 검증은 남아 있다. 이 노트북에는 현재16GiB 시작 여유 메모리와 물리Surround가 확보되지 않았으므로 현장 구동 완료라고 표현하지 않는다.
