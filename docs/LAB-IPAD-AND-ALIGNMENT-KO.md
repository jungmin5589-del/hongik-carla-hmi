# 연구실 연결과 시나리오 정렬

## 아이패드

2026-11-10 추가: **PC와 같은 Three.js 전체 내비**는
`http://연구실PC의IP:8776/m/navigation`으로 엽니다. PC QR 화면은
`http://127.0.0.1:8776/connect?view=tablet`입니다.
차량 3D·지도·음악·홍익 AI·선택·실행을 기존 UI로 제공합니다.
아래 `/m/`는 이전 간단 동반 화면 주소입니다.

주행·3면 렌더링은 연구실 PC가 담당하고, 아이패드는 같은 PC의 모바일 동반 화면으로 연결합니다. 내 노트북의 과거 IP를 사용하지 않습니다.

1. 연구실 PC에서 주행 앱과 모바일 게이트웨이를 실행합니다. 통합 시작 파일이 게이트웨이도 준비합니다.
2. PC 내비의 설정 → 휴대폰 연결에서 현재 QR을 엽니다. 또는 PC에서 `http://127.0.0.1:8776/connect`를 엽니다.
3. 같은 LAN/Wi-Fi의 아이패드 Safari에서 QR을 엽니다. 직접 입력할 때는 `http://연구실PC의IP:8776/m/`입니다. `127.0.0.1`은 각 기기 자신을 뜻하므로 아이패드에 입력하면 PC에 연결되지 않습니다.
4. 코드로 연결하고 상황 알림·AI 설명·선택 결과가 PC의 현재 주행에 반영되는지 확인합니다. 현재 연결 대상은 한 대이며 새 연결은 이전 아이폰 연결을 대체합니다.

PC와 아이패드가 서로 다른 망이거나 게스트 Wi-Fi가 기기 간 통신을 막으면 IP가 맞아도 연결되지 않습니다. 해당 연구실의 허용된 네트워크를 사용합니다. 포트 개방이나 보안 설정을 자동으로 바꾸지 않습니다.

잠금 화면 알림은 HTTPS 주소, 그 연구실 PC의 공개 인증서 신뢰, 홈 화면 앱과 알림 허용이 별도로 필요합니다. 과거 노트북의 개인 키나 인증서를 새 PC용으로 복사하지 않습니다. `/m/`는 간단 동반 화면이고, `/m/navigation`은 전체 내비입니다. 실제 iPad의 터치·소리·푸시 수신 검증은 현장에서 수행해야 합니다. [전체 내비 연결과 검증 범위](TABLET-FULL-NAVIGATION-KO.md)를 확인하세요.

## 웹소켓과 모바일은 별도 연결

연구실의 웹소켓(예: 8766)은 기존 시뮬레이터 프로그램의 연결입니다. 우리 모바일 게이트웨이는 현재 `127.0.0.1:8774/api/state`의 HMI 상태를 읽고, 선택을 같은 앱의 `/api/command`로 보냅니다. 웹소켓만 연결됐다고 모바일 상태까지 자동으로 이어지는 것은 아닙니다. 성공했던 현장 웹소켓 주소·실행 BAT·수정 파일은 보존해야 합니다.

`55_LAB_CONNECTION_CHECK.bat`은 연결 포트, 현재 엔진 지도·ego ID, 내비 위치와 모바일 게이트웨이 주소를 읽기만 해서 `lab-reports`에 저장합니다. 주행을 시작하거나 차량·모션을 움직이지 않고, 연결 코드·구독·개인 키를 보고서에 넣지 않습니다. 연구실에서 문제가 보이면 이 보고서와 해당 시나리오 이름을 함께 확인합니다.

## 수정 내용

- 주차·갓길·주행 차로를 실제 CARLA waypoint로 지도에 표시합니다. 카풀 차량을 도로 위로 억지로 옮겨 맞추지 않습니다.
- 왼쪽 차량 시각화에도 카풀의 실제 주차 차로와 주차 상태를 표시합니다. 주차 차로 중심에서의 오차를 주행 차로 이탈로 잘못 집계하지 않습니다.
- 지도 요청 중 다른 시나리오로 바뀌면 오래된 응답을 버리고, 일시적 지도 로드 실패는 재시도합니다.
- 출발 전 모든 차량의 실제 정지·위치·방향을 검사합니다. 지면에 내려앉는 시간을 고정 프레임 수만으로 판단하지 않습니다.
- 차량별 실제 바퀴 간격과 최대 조향각을 읽어 조향 계산에 반영합니다. 빠른 차는 직선에서 90km/h 목표를 유지하고 좁은 곡선 전에는 감속합니다.
- 빠른 차를 화면 밖 뒤쪽으로 재배치할 때 실제 정지 높이·회전 속도·조향 누적을 초기화합니다. 갱신 전 앞쪽 좌표로 뒤쪽 목표를 향해 급조향하지 않도록 그 프레임의 조향은 건너뜁니다.
- 현재 세션과 다른 내비에서 뒤늦게 온 조작은 거절합니다. 기존 UI·음악·AI 버튼 구조는 유지합니다.

## 현장 수정 보존

업데이트 패키지는 기존 소스가 마지막 전달본과 같은지 먼저 비교합니다. 연구실에서 웹소켓 연동 때문에 바꾼 파일이 있으면 전체 적용을 중단하고 원본을 보존합니다. 성공했던 현장 코드를 무조건 새 파일로 덮어쓰지 않습니다. `lab.local.json`, 모바일 연결 정보와 개인 키는 업데이트 대상에 포함하지 않습니다.

여기서의 로컬 CARLA 검증은 연구실 PC의 컨트롤러·웹소켓·3면 실측 검증을 대신하지 않습니다. 기존 0.9.15 및 모션 프로그램에 자동으로 연결하거나 변경하지 않습니다.

2026-11-09 로컬 검증에서는 일곱 상황의 초반 30초를 확인하고, 정체는 별도로 180초 동안 주행했습니다. 졸음 차량 거리 벌리기, 이상음 갓길 정차, 낙하물 회피, 카풀 위치 이동, 보행자 양보 안내, 안개 속 감속의 여섯 요청도 실제 CARLA API로 결과 완료와 접촉 기록을 확인했습니다. 모든 선택 조합이나 각 상황 전체 5분을 검사했다는 뜻은 아닙니다. 연구실에서만 보였다는 시작 충돌은 여기에서 동일하게 재현하지 못했습니다. 현장의 웹소켓 수정본과 실제 차량 제어 주체를 추가로 대조해야 합니다.
