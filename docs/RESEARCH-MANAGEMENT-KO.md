# 연구자료 관리와 4차로 시나리오 수정

2026-11-11. 기존 모션 연결·보정은 유지합니다.

## 4차로 시나리오

- 왼쪽 배경 차량은 실제 CARLA 경과 시간에 맞춰 90km/h로 이동합니다.
  차량을 ego 주변 구간에 순환 배치해 계속 지나가게 합니다. 이는 시나리오용 배경 교통입니다.
- 4차로 상황에서 클락션 선택지를 한 번 누르면 확인창·3초 대기 없이 내비에서 2.2초짜리 두 음 경적을 재생합니다.
  소리가 끝나면 주행을 종료하고 시나리오 선택 화면으로 자동 복귀합니다. 결과 관찰 대기는 없습니다.
- 오늘 실험의 '1차로로 진입하기' 요청은 실행 확인 후 현재 차로에서 감속·정차하고 종료합니다.
  차선 변경 성공으로 기록하지 않습니다. 실제 차선 변경은 실행하지 않습니다.

## 참가자 자료 화면

주소는 실행 중인 PC의 `http://127.0.0.1:8774/admin`입니다.
표와 CSV의 실험 날짜는 한국 시간 기준이며 실험 시작 시각을 기준으로 계산합니다.
아직 시작하지 않은 기록은 생성 날짜를 사용합니다.

### 자료 초기화

'자료 초기화'를 누르고 표시된 자료 수를 확인한 뒤 '초기화'를 입력합니다.
SQLite와 CSV를 로컬 `reset-backups`에 먼저 보관한 뒤 참가자·실험·행동 자료를 비웁니다.
진행 중인 실험이나 GitHub 업로드가 있으면 초기화하지 않습니다.
연결된 Drive 내보내기는 비워진 현재 자료로 갱신되며, GitHub에 올린 이력은 유지됩니다.

### 이름과 날짜를 포함한 GitHub 공개 저장

사용자가 이름을 유지한 공개 저장을 선택한 설정입니다.
'GitHub에 공개 저장'을 누르면 이름·날짜·실험 기록을 공개한다는 안내를 확인하고 저장할 수 있습니다.
저장소는 `jungmin5589-del/hongik-carla-hmi`, 자료 브랜치는 `research-data`입니다.
날짜별 `exports/YYYY-MM-DD/스냅샷/trials.csv`와 `events.csv`를 생성합니다.
소스 브랜치와 참가자 자료 브랜치는 분리하며, 연구 DB 전체나 인증정보는 업로드하지 않습니다.
연구자료 브랜치는 첫 실제 업로드 때 생성됩니다. 버튼 구현 검증에서는 실제 참가자 자료를 업로드하지 않았습니다.

업로드하려면 Git이 설치되어 있고 `jungmin5589-del` 계정으로 저장소 쓰기 권한이 있어야 합니다.
화면에서 업로드 진행·성공·오류와 저장한 자료 링크를 확인할 수 있습니다.
실패해도 PC의 원본 자료는 유지됩니다.

## 적용과 검증

Python 수정은 실행본을 다시 시작해야 반영됩니다. 내비게이션도 새로고침해 새 스크립트를 받습니다.
`HJI-2026-2/START_HONGIK_MOTION.bat`이 기존 6축 실행 파일입니다.
이전 앱이 실행 중이면 새 실행기가 그대로 재사용하지 않고 종료 후 재실행을 안내합니다.
장비의 기존 정지 절차를 따른 뒤 `live/Stop-CARLA-Native.bat`으로 종료하고 같은 시작 파일을 다시 실행합니다.
실제 장비 출력이나 실제 참가자 자료 삭제·업로드를 자동 검증에 사용하지 않습니다.
