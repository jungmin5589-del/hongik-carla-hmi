# 도로 위 낙하물 — CARLA 독립 시나리오

50번 CARLA 실행 → **07 / 도로 위 낙하물** → 내비의 출발.
기존 음악 플레이어·홍익 AI·별도 큰 주행 화면을 사용한다.

## 장면과 선택

- Town04, 우리 차량과 트럭 두 대, 구겨진 상자 물체 하나.
- 약 25km/h로 출발하고 주행 시계 10초 뒤 트럭 뒤쪽에서 물체를 방출한다.
- 상자는 생성 시 트럭 속도의 일부를 받고 중력·회전·도로 충돌로 떨어진다.
  주행 중 상자의 위치를 매 프레임 덮어쓰지 않는다.
- 트럭 내부의 고정 장치 파손은 모델링하지 않았다. 방출 지점에서 생성하는 연출이다.
- 차량은 낙하물 앞에서 감속한다. 홍익 AI 버튼을 눌러야 설명과 대응이 열린다.
- 네 버튼은 동등한 세로 배열이며 대응 화면에 ETA는 표시하지 않는다.

| 선택 | 처리 |
|---|---|
| 물체를 자세히 확인하기 | 정지 후 CARLA 카메라 화각을 85도에서 55도로 좁힌다. 재질·통과 안전성을 확정하지 않는다. |
| 피해서 지나가기 요청 | 같은 방향 왼쪽 차로와 근처 물리 차량을 확인한 뒤 저속 차로 변경. 공간이 없으면 정지 유지. |
| 멈춰서 기다리기 | 물체 앞에서 정지, 물체는 도로에 남는다. |
| 차량 판단에 맡기기 | 우선 감속·정지 후 공간이 확보되면 회피하는 고정 규칙. 학습형 판단 시스템이 아니다. |

선택만으로 실행하지 않는다. 기존 선택 → 실행 확인 → 실제 차량 반응 → 12초 결과 관찰 → 정차·완료 안내를 따른다.
회피 성공은 상자가 차량 뒤로 지나가고 실제 옆 차로 위치가 확인된 경우만 기록한다.
충돌은 ego 충돌 센서의 상대 actor ID와 실제 충격량으로 판정한다. 선택이나 타이머로 충돌을 만들어내지 않는다.

## 구현 범위와 한계

`fallen_cargo.py`의 상태기계와 물리 물체를 `native_carla.py`에 연결했다.
설명은 `city_voice.py`의 별도 Sohee 캐시를 사용한다. 주행 중 TTS 추론은 하지 않는다.
미리 준비한 상자를 사용하며, 종류를 모른다는 설명은 시나리오 조건이다. 실시간 YOLO 인식이나 불확실성 추정 결과가 아니다.
기본 차량 변형·파손이나 천 재질 비닐의 유체/천 시뮬레이션을 추가한 것은 아니다.
접촉음은 충돌 이벤트에 연결한 합성 효과음이며 실제 현장 녹음이 아니다.
배경 차량을 늘리기 전에 낙하·정지·회피의 반복성과 실제 출력 프레임을 검증한다.


## 개발 검증 (2026-11-04)

- 낙하 전후 실제 물체 높이 변화와 도로 위 잔류를 CARLA 실행에서 확인했다.
- 정지 선택은 물체 앞에서 멈추고, 회피 선택은 실제 옆 차로 위치와 물체를 지난 위치로 판정했다.
- 브라우저에서 Sohee WAV 재생 시간이 진행되는 것, 설명 후 세로 네 선택지, 실행 확인,
  정지 후 카메라 확대와 완료 안내를 확인했다.
- 단위/프로토콜 검사는 명시적 실행, 일시정지 시계, 빈 공간 대기, 실제 정지 후 위임,
  실제 통과 전 성공 금지와 실패 결과 문구를 검증한다.
- 정상 정지·회피 시험에서 충돌은 발생하지 않았다. 낙하물과 차량의 실제 충돌 연출을
  이번 검증에서 일부러 발생시킨 것은 아니며, 충돌 반응·소리의 실청 평가는 별도로 필요하다.
- 프레임 표시는 짧은 현재 출력 측정치다. 장시간 30fps 안정성·연구실 3면 화면·참가자 평가는 아직 하지 않았다.
